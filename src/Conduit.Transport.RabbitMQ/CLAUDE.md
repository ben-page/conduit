# Conduit.Transport.RabbitMQ

- `RabbitMQTransport` — extends `BrokerTransportBase<RabbitMQInboundMessage>`. Inbound dispatch, lifecycle, and outbound serialization handled by base class. Implements RMQ-specific primitives: AMQP channel management, topic exchange publishing, consumer management. Reply correlation is the base class's (`AwaitReplyAsync`/`CompleteReply`); the reply consumer copies `args.Body` before handing it over, because the client reuses the buffer.
- `UseRabbitMQ(connectionString?, configure?)` registers everything **keyed by endpoint name** — options, `RabbitMQTransport` (via `ActivatorUtilities.CreateInstance`, resolving the keyed options), a forwarding non-keyed `IConduitTransport` entry and a forwarding non-keyed `IHostedService` entry (each resolving the endpoint's keyed transport instance) — and calls `UseTransport<RabbitMQTransport>()`. No non-keyed `RabbitMQTransport`/options registration exists: two endpoints on RabbitMQ are two independent transport instances with independent options, never a shared last-write-wins singleton.
- Wire format: message body = serialized message (JSON), type in `Type` property, MessageContext in native `MessageId` property + historical `CausationId`/`ConversationId` headers (preserved so existing consumers and `ExtractContext` keep working unchanged). `ToRabbitHeaders` (the transport-local mapper; named apart from the base class's `BuildOutboundHeaders` to avoid a same-name, different-signature collision) additionally writes every header from the base class's assembled dictionary under its canonical `ConduitHeaders` key (`conduit-message-id`, `conduit-causation-id`, `conduit-conversation-id`, `conduit-source-app`), so both the historical and canonical forms are on the wire. `conduit-source-app` carries the publishing application's `ApplicationName` (omitted when unset) and is read by the [self-published event filter](../../docs/transports/index.md#self-published-events) on the inbound side.
- Request/response via exclusive auto-delete reply queue + `ReplyTo` + `CorrelationId` (used only for reply correlation, not MessageContext)
- **All messages flow through the topic exchange**: commands, queries, and events all publish to the single topic exchange with routing key = FullTypeName. Queue bindings route messages to the correct app queue. Reply messages bypass the exchange (direct to reply queue).
- Topology: idempotent `ExchangeDeclare`/`QueueDeclare`/`QueueBind`, always created on startup. Supports topology modes (Production = durable, Developer/Test = auto-delete). Resource names generated by `TopologyNaming`. No direct exchange — single topic exchange only. Pool-assigned types are excluded from the default app queue bindings to prevent dual delivery.
- Concurrency via `BasicQos` prefetch count. Options inherit `BrokerTransportOptions` (core): `DefaultConcurrency` and `ReceiverPoolOptions.Concurrency` both map to the prefetch count (cast to `ushort` at the consumption site).
- Type discovery via `ConduitTypeRegistry` (source-generated, compile-time verified) — no runtime DI scanning
- **Configuration keys** (`Conduit:Endpoints:{endpointName}`, bound by `ConduitConfigurationBinder.BindTransportOptions` before the `configure` callback runs): `ConnectionString` (required), `DefaultConcurrency` (default `10`), `ResponseTimeout` (default `00:01:00`), `Pools` (array of `{ Name, Concurrency, MessageTypes[] }` — see `AddPool` merge semantics in `src/Conduit/CLAUDE.md`). See [`docs/configuration-reference.md`](../../docs/configuration-reference.md#loading-from-iconfiguration) and [`docs/transports/rabbitmq.md`](../../docs/transports/rabbitmq.md#loading-from-configuration).
- Stop: `StopReceivingAsync` `BasicCancel`s the inbound consumers only (`inboundConsumers`, one channel each — a delivery is acked on its own channel, so the channels stay open for the drain, and so does the reply consumer). `StopConsumersAsync` closes the inbound channels (requeuing anything unacked) and the reply channel; `DisposeAsync` closes/disposes whatever is left plus the publish channel and connection.
