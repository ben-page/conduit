# Conduit.Audit

Operational audit trail for Conduit dispatch pipelines. Captures observations emitted by the generated mediator, consolidates them into per-dispatch records, and publishes them as `AuditBatch` events for local persistence or cross-service aggregation.

## Persistence engine (Conduit.Persistence)

Audit shares the relational-persistence abstraction in **`Conduit.Persistence`** with Durability. Audit depends on `Conduit.Persistence` only — it has **no** direct database-driver dependency (the `Microsoft.Data.Sqlite` PackageReference was removed). The engine is resolved from DI: `IConduitConnectionFactory` (connections) + `ISqlDialect` (engine type vocabulary). See `src/Conduit.Persistence/CLAUDE.md`.

- Register the engine on the **`ConduitBuilder`**, not the listener builder: `conduit.UseSqlite(connectionString)` (from `Conduit.Persistence.Sqlite`) — or `UsePostgres` / `UseSqlServer` / `UseMySql` — alongside `conduit.AddAuditListener(...)`. The engine is shared with Durability when both are configured (call `UseXxx` once).
- `DbAuditStore` extends `DbStoreBase`; `AuditTableInitializer` extends `TableInitializerBase`; `AuditPurgeService` extends `PeriodicCleanupServiceBase`.
- The audit dialects (`IAuditDialect` + `SqliteAuditDialect`/`SqlServerAuditDialect`/`PostgresAuditDialect`/`MySqlAuditDialect`), `IAuditConnectionFactory`, and `AuditConnectionStringFactory<T>` were **deleted** — their work moved into the shared `ISqlDialect`/`IConduitConnectionFactory` plus the module's own `AuditTableSchema` constants.

## Directory layout

- `Configuration/` — `AuditBuilder` (capture side), `AuditListenerBuilder` (persistence side), `AuditOptions`
- `Runtime/` — `AuditObserver`, `DispatchGroup`, `AuditPayloadCap`, `AuditBatchPublisher`, `AuditBatch`, `DispatchAuditRecord`, `LocalAuditListener`, `AuditPurgeService`, `AuditTableInitializer`
- `Persistence/` — `IAuditStore`, `DbAuditStore`, `AuditTableSchema` (module-owned table + column identifiers)

## Key types

- `AuditObserver` — `IConduitObserver` implementation. Receives `MessageObservation` callbacks from `MessageContext.Observe()`. Groups observations by `MessageId` in a `ConcurrentDictionary<string, DispatchGroup>`. Seals the group on `DispatchCompleted`/`DispatchFailed` and writes the resulting `DispatchAuditRecord` to a bounded channel. Filters out `AuditBatch` type observations to prevent infinite recursion. Also honours per-type suppression: it takes two `IReadOnlySet<string>` of full type names — **suppressed types** (no group is ever created, so nothing is recorded) and **suppressed-payload types** (group is recorded but the body is nulled out via `DispatchGroup.SuppressPayload()`). Only `DispatchInvoked` opens a group (`GetOrAdd`); any other observation looks its group up with `TryGetValue` and is dropped when there is none, so a late observation can never open a group without its `DispatchInvoked`. Every observation is timed by the observer's clock and handed to `DispatchGroup.Add(observation, observedAt)`. `EvictStaleGroups(now, staleTimeout)` evicts the groups that have taken **no observation** for `staleTimeout` before `now` (`DispatchGroup.SealIfInactive`: `now - LastObservedAt >= staleTimeout`, checked and sealed under the group's lock), not by `CreatedAt`, so a long dispatch that keeps observing stays open (`AuditObserverShould.KeepALongRunningDispatchAlive`); `now` is a parameter for deterministic testing. Evicted groups are sealed as failed (a synthetic `DispatchFailed`, `ExceptionType` `Conduit.Audit.StaleGroupEviction`) and flushed to the channel rather than dropped, preserving the partial trail. The sweep remembers each evicted group's `MessageContext` in a `ConditionalWeakTable` (weak keys: an entry lives as long as the dispatch's context) **before** removing the group from the dictionary (`TryRemove(KeyValuePair)`), so a terminal observation that arrives later, whether it finds no group (the table recognises its context) or finds the group already sealed (`Add` returns false and `IsEvicted` is true), is dropped and logged at Debug (EventId 522, `TerminalObservationAfterEviction`; the optional trailing `ILogger<AuditObserver>` constructor parameter, which `AddAudit`'s factory resolves; null logs nothing). The evicted record stands: a dispatch has one record (`AuditObserverShould.DropButLogACompletionThatArrivesAfterEviction`). Only the dispatch's own observations keep it open: a nested dispatch has its own group, so a handler silent for longer than the timeout is still evicted; the user guide points at `StaleGroupTimeout` (at most one day) or `MessageContext.Observe(new CustomObservation(...))` from the handler.
- `DispatchGroup` — internal type that accumulates observations for a single dispatch. Added to on the dispatching thread and sealed on another (the sweep, or a terminal observation racing it), so `Add`, `SuppressPayload`, `Seal`, `SealIfInactive` and `IsEvicted` all take its `Lock`: `Add(observation, observedAt)` appends and sets `LastObservedAt`, and returns false, adding nothing, once the group is sealed (the rejected-not-redirected choice: a late observation is dropped); `Seal()` marks the group sealed and returns a snapshot (`Observations` is a copy taken under the lock), so the old unsynchronized `List` race (`Add` against `Seal().ToList()`, an `ArgumentException` or "Collection was modified" on the sweep thread) cannot happen (`DispatchGroupShould.TolerateConcurrentAddAndSeal`). `SealIfInactive(now, staleTimeout)` (which replaced `MarkIncomplete`) appends the synthetic `DispatchFailed`, sets `IsEvicted`, and seals, in one critical section, or returns null when the group observed within the timeout or is already sealed. Holds the dispatch's `MessageContext` (`Context`: message ID, conversation ID, causation ID, properties). `Seal()` produces a `DispatchAuditRecord`, reading the context's payload (`MessageContext.Payload`, public: the captured body, readable by any observer) at that moment -- so a payload captured after `DispatchInvoked` (the wire path) is kept, and one cleared with `MessageContext.ClearPayload()` before the dispatch closes is dropped -- and passes it through `AuditPayloadCap` with the observer's `maxPayloadBytes`, so every seal path (terminal observation and stale eviction) is capped. `SuppressPayload()` nulls the captured body (for `SuppressPayload<T>()` types). `CreatedAt` is the record's `Timestamp`; `LastObservedAt` (initially `CreatedAt`) is the eviction reference time.
- `AuditPayloadCap` — internal. `Apply(payload, maxPayloadBytes)`: a body at or under the cap (UTF-8 bytes of the raw JSON) is returned as is; over it, the body is re-written from a `JsonNode` copy with every string value longer than one common cut length cut to that length + `…` (only where that shortens it on the wire; a cut never splits a surrogate pair; the `"•••"` placeholder is never cut), and a `$truncated: { bytes, cap }` member inserted first (replacing a body's own top-level `$truncated`, which under the cap is stored as is). It runs inside `OnObservation`, on the dispatching thread (~15 ms per MB over the cap). The cut length is the largest that fits, found by binary search over a size model (bytes outside string contents are fixed; a cut string costs its prefix's escaped length + the ellipsis's, via `JsonEncodedText`), then the result is written and re-measured. A non-object root, no fitting cut, a re-measured body still over the cap, or any non-OOM failure yields the marker alone. `ThrowIfInvalid` refuses an enabled cap below `AuditOptions.MinimumMaxPayloadBytes` (1 KB) with `ArgumentOutOfRangeException`, checked by the `AuditObserver` constructor; `AddAudit` checks the same floor through `AuditOptions.Validate()` (an `OptionsValidationException` failure).
- `AuditBatchPublisher` — `BackgroundService` that drains `DispatchAuditRecord` instances from the channel and publishes them as `AuditBatch` events via `IMediator.PublishAsync`. Takes both ends of the channel (`ChannelReader` and `ChannelWriter`, both DI singletons from `AddAudit`). Creates a new DI scope per batch for correct handler lifetime. Every publish runs under `CancellationToken.None`, so a stop never cancels a store write part-way (it used to pass the stopping token). `AuditBatch` is a plain event, so a listener failure throws out of the publish: the drain loop catches and logs it, drops that batch and drains the next, so a failing audit store never ends the service or stops the host; a failure while stopping is logged the same way (it used to end the loop with no log). Batch size controlled by `AuditOptions.BatchSize`. **The drain loop never observes the stopping token**: `WaitToReadAsync()` returns false once the writer is complete and the channel empty. **`StopAsync`** completes the writer (`TryComplete`: the observer's later `TryWrite`s fail, so a record sealed after the stop began is not recorded), then calls `base.StopAsync` with a token linked to the host's and `CancelAfter(ShutdownGrace)` (real time): the base cancels the stopping token (ending the sweep) and waits for `ExecuteTask` until that token fires, never throwing for it. Then `Abandon()`, under `drainGate` (the lock `TakeBatch` also takes), sets `abandoned` (so `TakeBatch` returns nothing more), counts the batch in flight (`inFlightCount`, set by `TakeBatch`, cleared after each publish) plus the records still queued (read off with `TryRead`, which leaves the completed channel finished, so the loop ends), and a non-zero count is one Warning, EventId 520 `AuditRecordsAbandoned` (`AuditBatchPublisherShould.DrainOnStop`, `.LogTheRecordsLeftWhenTheGraceEnds`). A batch in flight when the grace ends keeps running under `None` and may still finish; it is counted as not published at that moment. `Dispose` (a host disposed without a stop) completes the writer and abandons too, so the loop does not wait forever. Also runs a concurrent `PeriodicTimer` sweep loop on the stopping token that calls `AuditObserver.EvictStaleGroups` to evict inactive dispatch groups (sweep cadence = `min(StaleGroupTimeout, 1 minute)`); a sweep that throws is logged at Error (EventId 521, `StaleGroupSweepFailed`) and the loop carries on, where it used to catch only OCE and fault `ExecuteAsync`, stopping the host (`.KeepSweepingAfterASweepThrows`, a `ThrowingTimeProvider` host). This is the single owner of stale-group eviction. **Stop order**: `AddAudit` runs inside the `configure` callback, which `AddConduitCore` invokes before it registers `ConduitBackgroundDispatcher`; the host stops hosted services in reverse registration order, so the dispatcher stops (its queued fire-and-forget work run, records sealed) before the publisher drains (`AuditRegistrationShould.RegisterThePublisherBeforeTheBackgroundDispatcher`). A hosted service registered before `AddAudit` (before `AddConduit`, or a transport whose `Use*` precedes `AddAudit` in the callback) stops after the publisher, and its last dispatches are not recorded: documented in `docs/audit.md#shutdown`, not solved. `HostOptions.ServicesStopConcurrently` removes the order altogether.
- `AuditBatch` — `IEvent` record containing `SourceService`, `SourceHost`, `BatchTimestamp`, and `Records`. Marked `[DoNotAudit]` to prevent the audit infrastructure from auditing its own events.
- `DispatchAuditRecord` — the consolidated audit record for a single dispatch: message context fields, type info, raw JSON payload, properties, timestamp, and the full observation list.
- `LocalAuditListener` — `IEventListener<AuditBatch>` (transient) that persists records to `IAuditStore`. Registered by `AddAuditListener`, whether batches are published in-process or arrive over a transport. It is `[NotAutoRegistered]`, so `AuditListenerBuilder` also calls `ConduitTypeRegistry.ActivateEvent` for `AuditBatch`: without it a central collector's broker transport would never subscribe the batches (`AuditListenerRegistrationShould`). Resolved per-publish inside the dispatch scope, so it can consume the **Scoped** `IAuditStore`.
- `AuditPurgeService` — extends `PeriodicCleanupServiceBase`. Periodically deletes expired records based on `AuditOptions.RetentionPeriod`. The base class runs each tick inside a fresh `IServiceScopeFactory` scope and the purge resolves `IAuditStore` from that scoped provider in `CleanupAsync` — it does **not** inject the store into the constructor. This avoids a captive-dependency bug: the store is now Scoped, so a singleton `BackgroundService` injecting it directly would throw "Cannot consume scoped service from singleton" at startup under `ValidateScopes`.
- Observer attachment — there is no process-global observer. `AddAudit` registers `AuditObserver` as a DI singleton exposed as `IConduitObserver`; the generated mediator resolves it from each dispatch's scope and attaches it to that dispatch's `MessageContext` (`AttachObserver`), so each host observes only its own dispatches.
- `AuditTableInitializer` — extends `TableInitializerBase`. Creates the audit table at startup (scoped) and **fails fast** in `ValidateConfiguration` if `AddAuditListener` was called but no persistence engine (`IConduitConnectionFactory`/`ISqlDialect`) is registered, pointing at `conduit.UseSqlite(...)`.

## Time

**Nothing in this project reads the ambient clock.** `grep -rn "DateTime.UtcNow\|DateTimeOffset.UtcNow" src/Conduit.Audit/` must return nothing. `AddAudit` and `AddAuditListener` both register `TryAddSingleton(TimeProvider.System)`, so a host's own `TimeProvider` (a test's `FakeTimeProvider`) wins. `AuditObserver` takes it as an optional trailing parameter of its full constructor (null, as the shorter constructors pass, is `TimeProvider.System`; `AddAudit`'s factory resolves it) and reads it on every observation: the first stamps the `DispatchGroup` (`DispatchGroup`'s constructor takes `createdAt`, the record's `Timestamp`), and each sets the group's `LastObservedAt`, the inactivity `EvictStaleGroups(now, ...)` compares. `AuditBatchPublisher` reads it for `BatchTimestamp` and for the sweep's `now`; `AuditPurgeService` counts the retention cutoff back from it. Both take it as an optional trailing constructor parameter. The sweep's `PeriodicTimer`, the publisher's `ShutdownGrace` and the purge's interval stay real time. Tests: `AuditObserverShould.StampARecordAndAgeItsGroupByTheInjectedClock`, `AuditPurgeServiceShould.PurgeByTheInjectedClock` (`PurgeRecordingAuditStore`), `AuditBatchPublisherShould.StampABatchAndItsRecordsWithTheHostsClock` (`PublishedAuditBatches`, whose listener records only in a host that registers the collector), `AuditRegistrationShould.RegisterTheSystemClockUnlessTheHostHasOne`.

## Configuration

Two orthogonal entry points on `ConduitBuilder` — **`AddAudit`** captures, **`AddAuditListener`** persists. Compose them per deployment role.

**`AddAudit()`** — registers the capture pipeline (observer, channel, batch publisher) that emits `AuditBatch` events. Used by any service that wants its own dispatches audited:
```csharp
conduit.AddAudit(audit =>
{
    audit.ServiceName = "OrderService";
    audit.BatchSize = 50;
});
```

**`AddAuditListener()`** — registers the `IEventListener<AuditBatch>`, store, table initializer, and retention purge. The events it consumes may be published in-process (paired with `AddAudit`) or arrive over a transport from other services — it handles both identically. It owns retention (`RetentionPeriod`/`PurgeInterval`). The persistence engine is configured separately on the `ConduitBuilder` (`conduit.UseSqlite(...)`) and shared with Durability via DI — `AuditListenerBuilder` no longer has `UseSqlite/UsePostgres/UseSqlServer/UseMySql`:
```csharp
conduit.UseSqlite("Data Source=audit.db");          // engine on the ConduitBuilder, shared with durability
conduit.AddAuditListener(listener =>
{
    listener.RetentionPeriod = TimeSpan.FromDays(30);
});
```

Deployment roles:
- **Producer only** (ships audit to a collector): `AddAudit()` alone.
- **Single service, stores own audit**: `conduit.UseSqlite(...)` + `AddAudit()` + `AddAuditListener(...)`. On a broker shared with other audited services it stores their batches too (`AddAuditListener` activates `AuditBatch`, as any registered listener subscribes its event: deliberate, and there is no opt-out knob). The user guide (`docs/audit.md#deployment-roles`) gives the two ways to keep it to its own: exclude `AuditBatch` from the registry before the host starts, or replace `LocalAuditListener` with a listener filtering on `SourceService`.
- **Central collector** (persists `AuditBatch` from many services): `conduit.UsePostgres(...)` + `AddAuditListener(...)` alone (no `AddAudit`).

`AuditBuilder` exposes public properties for capture tuning (`ServiceName`, `BatchSize`, `ChannelCapacity`, `BackpressureMode`, `StaleGroupTimeout`, `MaxPayloadBytes` -- passed to the `AuditObserver` constructor, which hands it to each `DispatchGroup`) plus `Suppress<T>()` (skip all recording for a type) and `SuppressPayload<T>()` (record observations but omit body). Both suppression methods are wired: `AddAudit` resolves their `Type` sets to full-type-name sets and passes them to `AuditObserver`, and also hands every suppressed `Type` to `ConduitRuntime.SuppressAuditPayloadOf` (public but `[EditorBrowsable(Never)]`: Conduit has no `InternalsVisibleTo` for this package), so an `[AuditAs]` envelope member holding one is left out of `AuditJsonOptions`' output instead of carrying the suppressed body inside another message's payload. That lookup is process-wide and add-only, like `AuditJsonOptions` itself: a type any host in the process suppresses is left out of every host's `[AuditAs]` capture. `StaleGroupTimeout` is wired into the `AuditBatchPublisher` sweep, `ShutdownGrace` (default 5 s) into its stop. `AuditListenerBuilder` exposes `RetentionPeriod` and `PurgeInterval`. The builders' properties delegate to an internal `AuditOptions`, which the `AddAudit`/`AddAuditListener` extensions copy into `IOptions<AuditOptions>`. Persistence is purely event-driven via `LocalAuditListener`, which is why local and distributed storage share one entry point.

**Validated options.** `AddAudit` and `AddAuditListener` call `AuditOptions.Validate()` on their builder's options once the callback has run (each builder has its own `AuditOptions`, so the other side's fields are defaults and pass). It collects every failure and throws one `OptionsValidationException` (Durability's shape): `BatchSize` and `ChannelCapacity` positive (`BatchSize <= 0` made `DrainBatch` return nothing while `WaitToReadAsync` kept returning true: a busy loop from the first record); `StaleGroupTimeout` positive and at most one day (`<= 0` made `new PeriodicTimer` throw inside `ExecuteAsync`, stopping the host); `ShutdownGrace` not negative and at most one day (zero abandons the queue at once); an enabled `MaxPayloadBytes` at least 1 KB (`0` or less is still "no cap"; this replaced `AddAudit`'s `AuditPayloadCap.ThrowIfInvalid` call, so the failure is an `OptionsValidationException` now); `PurgeInterval` positive and at most one day; `RetentionPeriod` positive and at most 3650 days. The ceilings mirror Durability's `DurationLimits` as private constants, as `JobsOptions` does, since Audit does not reference Durability. Tests: `AuditOptionsShould.RejectNonPositiveValues`, `.RefuseADurationAboveItsCeiling`, `.AcceptEveryCeilingAndAZeroGraceExactly`, `PayloadCapConfigurationShould.RefuseACapTooSmallForTheMarker`.

**No metrics aggregation.** Audit captures the full observation trail; it does not compute metrics. The previously-inert `AuditOptions.FlushInterval` and `AuditOptions.MetricsAggregationInterval` knobs (and `AuditBuilder.FlushInterval`) were **removed** — there was no flush timer (the `AuditBatchPublisher` flushes only when `BatchSize` accumulates or the channel signals readable) and no aggregation feature. Real-time metrics come from the built-in OpenTelemetry `"Conduit"` `Meter` (`ConduitTelemetry`), not from audit.

## Observation flow

1. Generated mediator calls `MessageContext.Observe(observation)` at dispatch boundaries (`DispatchInvoked`, `DispatchCompleted`, `DispatchFailed`)
2. The context's attached observer (this host's `AuditObserver`, attached per dispatch by the generated mediator) receives it in `AuditObserver.OnObservation`
3. Observer groups observations by `MessageId` in `DispatchGroup`, seals on terminal observation
4. Sealed `DispatchAuditRecord` written to bounded `Channel<DispatchAuditRecord>`. `AuditObserver` seals at once (the payload is readable only then), and the **write** waits when `context.Attempt` is set: `attempt.OnKept(() => channel.TryWrite(sealed))` writes the record once the attempt is kept and drops it if the attempt is abandoned for a retry (see `docs/dispatch-retry.md`). `context.Attempt` is non-null only for a dispatch from a running attempt's own scope (the generated mediator binds it), so the dispatch that owns the attempts, an independent dispatch from another provider, and every dispatch in a host with no retry policy are written as they seal. The held record is a sealed value; stale-group eviction is unchanged. The owner's one record carries a `RetryAttempted` per retry. `OnKept` work should not throw: it runs after the attempt's own try, so an exception from it is never offered to the policy and reaches the dispatch's caller in place of its result (or the kept attempt's own exception). A nested dispatch whose effect leaves the attempt (a local `[FireAndForget]` command or event, an un-outboxed transport broadcast, a routed send) is bound like any other, so its record is dropped with an abandoned attempt although the effect happened: the audit under-records it (`docs/audit.md`, Records and retried attempts).
5. `AuditBatchPublisher` drains channel, publishes `AuditBatch` event via mediator under `CancellationToken.None` (a failed publish is logged and the batch dropped; on stop, the queue is drained for `ShutdownGrace` at most)
6. `LocalAuditListener` (or any `IEventListener<AuditBatch>`) persists to store

- **Outbox delivery rows**: the outbox's local delivery (`ILocalEnvelopeDispatcher.PublishLocalEnvelopeAsync`, see Conduit.Durability) is an observed dispatch, so each delivery attempt seals its own `DispatchAuditRecord`: `MessageKind` `"Event"`, `MessageType` = the envelope type, a fresh `MessageId`, `CausationId` = the outbox entry's `MessageId`, `ConversationId` = the entry's, observations `DispatchInvoked` then the listener's handler observations then `DispatchCompleted`/`DispatchFailed`, and `Payload` always null (the publish record holds the body). `MessageKind` `"Event"` and the publish record's `"event"` differ only by case, so a case-insensitive store collation cannot tell them apart in SQL.

## Capture serializer (`AuditJsonOptions`)

Moved here from the user guide, which keeps only the consequences (marks shape the captured body only, they are inherited, raw-JSON members are verbatim unless marked). Member-level capture serializes with `ConduitRuntime.AuditJsonOptions` (core): `JsonOptions` plus a modifier that drops `[DoNotAudit]` properties (and the properties bound to marked constructor parameters), writes `[AuditRedacted]` ones as their placeholder, and types `[AuditAs]` ones. Names match case-insensitively, and base types are walked: a base record's marked parameter counts, and so does a mark on a base virtual property its override does not repeat. Wire serialization keeps `JsonOptions`, so the member still travels on the wire. The modifier acts on members it can see as CLR properties, which is why a raw-JSON member — `JsonElement`, `JsonElement?`, `JsonNode`, `JsonDocument` or `object` (the serializer reads `object` as a `JsonElement`), or a `[JsonExtensionData]` bag — is captured verbatim, with any marked value inside it in clear, unless the member itself is `[AuditAs]`, `[DoNotAudit]` or `[AuditRedacted]`.

## Recursion suppression

Recursion (auditing the `AuditBatch` publish itself) is prevented by `AuditObserver`, which explicitly skips `DispatchInvoked` observations where `MessageType` matches `AuditBatch`. `AuditBatch` is also marked `[DoNotAudit]`, but note that `[DoNotAudit]` only suppresses **payload capture** in the generated code (`MediatorEmitter` gates the `SetPayload` call on `!isDoNotAudit`) — `Observe()` calls are still emitted for `[DoNotAudit]` types. So the observer's type filter, not the attribute, is what actually breaks the recursion.

## Persistence

- `IAuditStore` — interface: `SaveBatchAsync`, `GetByMessageIdAsync`, `PurgeExpiredAsync`, `EnsureTableExistsAsync`. Registered **Scoped** by `AddAuditListener` (it depends on the Scoped `IConduitConnectionFactory`).
- `DbAuditStore` — extends `DbStoreBase`; depends on `IConduitConnectionFactory` + `ISqlDialect` (resolved from DI). `EnsureTableExistsAsync` runs its create through `DbStoreBase.EnsureCreatedAsync`, so a replica that loses a concurrent create of `conduit_audit` passes over the engine's already-exists error and starts. Composes its CREATE TABLE DDL from the dialect's type-name helpers (`BigIntAutoIncrementPrimaryKey`, `TextType`/`NullableTextType`, `TimestampType`) and its own `AuditTableSchema` identifiers; the insert / select-by-message-id / delete-expired-purge SQL are module-owned constants (identical across engines, like durability's CRUD). Table `conduit_audit`; uniform PascalCase columns across all engines (Postgres folds unquoted identifiers to lower case transparently — no more snake_case aliasing).
- `AuditTableSchema` — module-owned `static` constants for the table + column names. Mirrors durability's `OutboxTableSchema`.
- **One connection, one transaction per batch**: `SaveBatchAsync` opens one connection, begins a transaction, inserts every record through `DbStoreBase.ExecuteOnConnectionAsync` and commits after the last; a failing record throws, and the uncommitted transaction rolls back as it is disposed (the `DbJobStore` pattern), so nothing of the batch persists and the publisher's "batch dropped" log is the truth. It used to open a connection per record with no transaction, so a failure at record 60 kept 59. `DbAuditStoreShould.WriteABatchAtomically` (a `CountingConnectionFactory`: one connection, none of five records kept when the third cannot be bound); the transaction shape on the server engines is exercised by `PersistenceEngineTestBase.RoundTripAuditBatchWithFullTimestampPrecisionAndPurge`.
- **UTC timestamps via ISO 8601 text**: matching the durability stores, `DbAuditStore` writes timestamps as round-trippable UTC ISO 8601 text (`DateTime.ToString("O")`) and parses them back with `DateTimeStyles.RoundtripKind`, stamping `DateTimeKind.Utc`. This is engine-agnostic — it needs no per-engine `DbType` and no native-datetime binding, so the audit module did **not** require adding an audit-specific timestamp primitive to `ISqlDialect`. (The previous native-`DateTime`-binding approach with `DbType.DateTime2`/`DbType.Object` was the only thing genuinely divergent across audit's old dialects; switching to durability's text approach removed the divergence entirely.) Full tick precision is preserved by the `"O"` round-trip format.
- **No audit dialects.** The four audit dialect classes + `IAuditDialect` + `IAuditConnectionFactory` + `AuditConnectionStringFactory<T>` were deleted; the engine type vocabulary lives in the shared `ISqlDialect` (covered per-engine by the Durability project's `PostgresDialectShould`/`SqlServerDialectShould`/`MySqlDialectShould`/`SqliteDialectShould`). The audit module's composed CREATE TABLE DDL is asserted per-engine by `AuditStoreSqlShould` (no DB), and the full composed CRUD is covered functionally by `LocalAuditStoreShould` round-tripping against real SQLite. The Singleton→Scoped lifetime safety is proved by `AuditScopeValidationShould` (builds the host under `ValidateScopes`/`ValidateOnBuild` and exercises the purge + dispatch paths).

## Zero-cost when not opted in

When `AddAudit()` is not called, `MessageContext.Observer` remains null. The generated mediator's `Observe()` calls are guarded by a null check, making the audit infrastructure zero-cost when not configured.
