# Conduit.Transport.Kafka

User guide: [`docs/transports/kafka.md`](../../docs/transports/kafka.md) — setup, options, configuration keys, topology, pools, wire format. Keep user-facing facts there, not here.

- `KafkaTransport` — extends `BrokerTransportBase<KafkaInboundMessage>`. Uses `Confluent.Kafka`. Inbound dispatch, lifecycle, and outbound serialization handled by base class. Implements Kafka-specific primitives: producer/consumer management, consumer group routing, dead-letter topic publishing.
- `UseKafka(bootstrapServers?, configure?)` registers everything **keyed by endpoint name** — options, `KafkaTransport` (via `ActivatorUtilities.CreateInstance`, resolving the keyed options), a forwarding non-keyed `IConduitTransport` entry and a forwarding non-keyed `IHostedService` entry (each resolving the endpoint's keyed transport instance) — and calls `UseTransport<KafkaTransport>()`. No non-keyed `KafkaTransport`/options registration exists: two endpoints on Kafka are two independent transport instances with independent options, never a shared last-write-wins singleton.
- **Default groups own the complement of pool-claimed types.** Both default groups (shared/unicast for commands+queries, per-app/multicast for events) subscribe to the same shared topic and filter client-side on the `conduit-type` header. A non-owned message is skipped **but its offset is still committed** — not committing would block every subsequent message in the partition.
- **Concurrency = N consumer instances per consumer group.** `BuildConsumerGroupSpecs` produces one spec per group; `StartConsumersAsync` starts `InstanceCount` `IConsumer` instances in the same `group.id`, and Kafka balances partitions across them. Instance count is clamped to `KafkaTopologyManager.SharedTopicPartitions` (6) — more instances than partitions sit idle, since a partition is assigned to exactly one consumer in a group.
- **Pools = dedicated consumer groups**, each with a deterministic topology-mode-aware `group.id` (`pool-{name}` suffix on the shared/unicast id for its command/query types, on the per-app/multicast id for its event types). Same isolation guarantee as the queue-based transports, achieved with groups instead of queues.
- **Outbound partition key** is the per-message id (`PartitionKey(headers)` reading `headers[ConduitHeaders.MessageId]`, fallback fresh GUID — from the header dictionary `BrokerTransportBase` assembles per publish, never ambient state). Distributing the key is what lets a group with concurrency > 1 process same-type messages in parallel; the type discriminator rides in the `conduit-type` header so partition routing stays independent of type. There is no cross-message ordering contract between distinct dispatches.
- Kafka's on-wire header names have always matched `ConduitHeaders`' canonical keys, so — unlike RabbitMQ/ASB/ActiveMQ — nothing here is a dual or renamed form. `conduit-source-app` is read by the [self-published event filter](../Conduit/CLAUDE.md) on the inbound side.
- `AbandonAsync` commits the offset and publishes to the dead-letter topic immediately. No in-process retry: Kafka offsets are sequential, so holding a failed message back stalls everything behind it.
- `KafkaTopologyReaper.ReapByPrefixAsync(bootstrapServers, prefix)` — public best-effort cleanup deleting topics + consumer groups by name prefix. Used by the test harness once per project against its `test-{hash}-` prefix; also available to apps. Replaces the removed no-op `CleanupLoopAsync` timer.
- Type discovery via `ConduitTypeRegistry` (source-generated, compile-time verified) — no runtime DI scanning.
- `UseKafka`'s private `ApplyDottedKeys` runs after `ConduitConfigurationBinder.BindTransportOptions` and accepts the native dotted spelling (`ProducerConfig:linger.ms`) via `ClientConfig.Set`, since the binder matches on C# property names and silently drops a dotted key. It only materializes `options.ProducerConfig`/`ConsumerConfig` when that section actually has a dotted key to apply, so an endpoint with no Kafka-specific configuration leaves both `null` for a `configure` callback that branches on it.
