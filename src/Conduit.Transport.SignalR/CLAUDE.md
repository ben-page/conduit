# Conduit.Transport.SignalR

- `ConduitHub` — inbound SignalR hub with `Dispatch(type, payload, context?, headers?)` and `Publish(type, payload, context?, headers?)` methods, injects `IWireMediator` and `IEnumerable<IDispatchContextEnricher>` via constructor. Both optional params are `Dictionary<string, string>?`:
  - `context` carries `MessageContext` correlation (`MessageId`, `CausationId`, `ConversationId`) for cross-service propagation — browser clients pass `null` (the server mints fresh IDs), C# clients populate it.
  - `headers` carries caller-supplied values (e.g. tenant code). `StartMessageContext` seeds the property bag from `headers`, then runs registered enrichers via `DispatchContextEnrichment.Apply(enrichers, Context.User, ...)` — enrichers run **last** so server-trusted values (e.g. authenticated user id) overwrite any spoofable client header. The merged bag flows into `MessageContext.Properties` via `StartDispatchFromTransport(messageId, causationId, conversationId, properties)`, reaching pipeline behaviors. When `properties` exist but no correlation is supplied, fresh IDs are minted so the properties still reach the generated mediator.
- `SignalRTransport` — outbound dual-mode transport with lazy connect (`EnsureConnectedAsync`). `UseSignalR(hubUri?, configure?)` binds `SignalROptions` from the endpoint's configuration section (`builder.Configuration?.Bind(options)`), applies the `hubUri` argument and then the `configure` callback if given, registers **both** the bound `SignalROptions` and the `SignalRTransport` as keyed singletons by endpoint name (matching the broker transports' pattern — the options are inspectable, not bound and dropped), and calls `UseTransport<SignalRTransport>()`. Client mode sends `MessageContext.Current` correlation as the `context` dictionary (built by `BuildContext()`). It always invokes the hub with **all four args** — `Dispatch`/`Publish`/`RedeliverAsync` pass `noHeaders = null` for the `headers` arg because SignalR rejects arity mismatches on the wire (the outbound transport does not forward headers itself).
- `AddConduitSignalR()` registers SignalR services and server-mode transport as non-keyed `IConduitTransport` (for event broadcast to connected clients)
- **Dual-mode SignalRTransport**: Server mode (IHubContext, pushes events) and client mode (HubConnection, sends commands + receives events). Client mode uses lazy connect (auto-starts on first use via `EnsureConnectedAsync`).
- **Configuration keys** (`Conduit:Endpoints:{endpointName}`, bound before the `configure` callback runs): `HubUri` (required). See [`docs/configuration-reference.md`](../../docs/configuration-reference.md#loading-from-iconfiguration) and [`docs/transports/signalr.md`](../../docs/transports/signalr.md#client-mode-service-to-service).
