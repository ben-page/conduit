# Conduit.SourceGen (netstandard2.0)

- `EnforceExtendedAnalyzerRules=true`, `IsRoslynComponent=true`, `NoWarn=RS2008`
- Auto-discovers ALL types implementing `ICommand`, `IQuery`, `IEvent` across the full compilation graph (no attributes needed). Cross-assembly discovery is intentional for shared contract libraries. Discovery walks `compilation.GlobalNamespace` plus referenced assemblies via `RoslynScanner` — discovery-by-interface across non-source (metadata) assemblies cannot be expressed through syntax providers / `ForAttributeWithMetadataName`, so the whole-`Compilation` walk is required.
- **Incrementality (emission cached; walk is not):** `ConduitGenerator.Initialize` wires `CompilationProvider.Select(BuildModel).WithTrackingName("BuildModel")` → `RegisterSourceOutput(Emit)`. `BuildModel` produces a value-equatable `ConduitModel` (records + `EquatableArray<T>`, no `ISymbol`/`Compilation` captured), so Roslyn skips re-emission when discovery is unchanged (asserted by `IncrementalCachingShould`). **The cross-assembly symbol walk still re-runs every keystroke** because its input (`Compilation`) always changes and discovery-by-interface across metadata assemblies can't use `ForAttributeWithMetadataName`; only the emission is cached. Hard rule: never capture a `Compilation`/`ISymbol` in `ConduitModel` — it silently defeats the cache. Listener-group order is pinned (`OrderBy` on the event type name) so the cached model is deterministic across `Dictionary` enumeration order.
- **Nested-type FullTypeName parity contract:** `DispatchableTypeInfo.FullTypeName` and the handler/event message-type keys (`HandlerInfo.MessageFullTypeName`, `ListenerGroup.EventFullTypeName`) hold the **metadata** full name — nested types joined to their container with `+` (e.g. `Ns.Outer+Inner`), matching the runtime `Type.FullName`, the wire discriminator, the `ConduitTypeRegistry` key, and `Conduit.TypeGen.ReflectionScanner` (which uses `type.FullName`). `RoslynScanner.GetMetadataFullName` builds this by walking the `ContainingType` chain (not a string-replace). Because this metadata form is invalid C# source for nested types (C# uses `.` for nested member access), emitters call `EmitConstants.ToCSharpTypeRef` to convert `+`→`.` whenever the name is written into a **C# syntax position** (type declaration, generic argument, `typeof(...)`, type-pattern) while emitting `FullTypeName` verbatim only into **string-literal discriminators**. Handler/listener implementation names (`HandlerFullTypeName`, `ListenerFullTypeNames`) stay in `ToDisplayString()` (`.`) form — they are only ever C# type references.
- Reads `[LocalOnly]` attribute to suppress event broadcast in generated code
- Reads `[FireAndForget]` attribute: F&F void commands emit `Execute` (background dispatch) + `ExecuteVoidWire` (inline for wire-inbound). F&F events enqueue local listeners to background dispatcher, broadcast to transports inline. CONDUIT003 diagnostic for F&F on result types/queries.
- Reads `[assembly: RemoteContracts("Ns")]` to suppress CONDUIT001 for types in remote contract namespaces
- Reads `[NotAutoRegistered]` (`Conduit.Attributes.NotAutoRegisteredAttribute`) in `RoslynScanner` to exclude a handler/listener from auto-registration (still discoverable as a message, just not auto-wired)
- **The attempt boundary (`DispatchEmitter`).** The handler-running `ConduitDispatch` methods keep their public signatures and become a call to `ConduitRuntime.DispatchAttemptsAsync<TRequest, TResult>(serviceProvider, attemptServices => <Method>Attempt(request, attemptServices, conduitOptions, cancellationToken), cancellationToken)`; the old body moves, unchanged, to a private `ExecuteAttempt` / `FetchAttempt` / `ExecuteVoidWireAttempt`. Command with a result: `Execute` / `ExecuteAttempt` over `Task<TResult>`; void command: `DispatchAttemptsAsync<TCmd, object>` with an async lambda returning `(object)Unit.Value`; query: `Fetch` / `FetchAttempt`; `[FireAndForget]` wire: `ExecuteVoidWire` / `ExecuteVoidWireAttempt`, still answering `Unit`. The `[FireAndForget]` local `Execute` (the enqueue) and `ExecuteVoid` are not routed through the boundary. `EmitDispatchParameters` and `EmitAttemptsCall` write the shared parameter list and the call; every type position goes through `EmitConstants.ToCSharpTypeRef` (a nested type's `+` form is not valid C#). Without a policy, nested, or uncovered, the runtime calls the attempt once on `serviceProvider`, so the emitted dispatch behaves as if the body were inline.
- **Binding the context (`MediatorEmitter`).** `EmitContextStart` and `EmitWireContextStart` emit `ConduitRuntime.BindDispatchAttempt(MessageContext.Current, serviceProvider);` on the line after `AttachObserver` and before the first observation, via `EmitBindDispatchAttempt`. A top-level dispatch's context is started before `ConduitDispatch` runs, so it binds to no attempt and stays one context across every attempt; a dispatch from the running attempt's own scope binds to that attempt. The model is unchanged (no `ISymbol` captured).
- **Dispatch metrics (`MediatorEmitter`).** Every dispatch the mediator observes -- the in-process `ExecuteAsync`/`FetchAsync`/`PublishAsync`, the wire `DispatchRequestAsync`/`DispatchEventAsync`, and the outbox's `PublishLocalEnvelopeAsync` -- emits `__dispatchType`/`__dispatchKind` (deconstructed from a `(Type, Kind)` tuple) and its stopwatch through `EmitDispatchMetricStart`, then calls `ConduitTelemetry.RecordDispatch` exactly once: `success: true` beside each `DispatchCompleted` (`EmitDispatchCompleted`), `success: false` in the catch that observes `DispatchFailed` (`EmitDispatchFailed`). The kind is lowercase `command`/`query`/`event`. A wire request's tuple comes from the emitted `WireRequestMetric(type)` switch over the compilation's declared commands and queries, and a wire event's or outbox envelope's from `EventMetric(type)` over its events: the type name is the caller's, so a name the compilation does not declare (route-forwarded, or handled nowhere) is tagged `UndeclaredMetricType` (`(undeclared)`; kind `request` or `event`) and a caller cannot mint metric series. The audit observation's kind (`Request`/`Event` on the wire) is unchanged.
- Emits: `ConduitDispatch.g.cs`, `ConduitRegistration.g.cs`, `ConduitMediator.g.cs`, `ConduitRestEndpoints.g.cs` (conditional), `ConduitResilienceDispatch.g.cs` (conditional)

## Diagnostics (`DiagnosticDescriptors.cs`)

- **CONDUIT001** — *No handler found* (Warning): a command or query has no local handler and is not marked as a remote contract. Suppress for remote contract namespaces with `[assembly: RemoteContracts("Ns")]`.
- **CONDUIT002** — *Multiple handlers found* (Error): more than one handler exists for a command/query; only one handler per command/query is allowed.
- **CONDUIT003** — *Invalid [FireAndForget] usage* (Warning): `[FireAndForget]` is only valid on void commands (`ICommand`) and events (`IEvent`). Commands with results (`ICommand<TResult>`) and queries (`IQuery<TResult>`) require a response.
- **CONDUIT004** — *Handler not accessible* (Warning): a handler for a type exists in a referenced assembly but is not accessible to the generating assembly. Make it `public` to be auto-registered.
- **CONDUIT005** — *Conflicting audit marks* (Error): a message member (property or record/constructor parameter, base chain included) is marked both `[DoNotAudit]` and `[AuditRedacted]`; an audited member takes one. Mirrors the runtime refusal in `ConduitRuntime.ApplyAuditMemberMarks`.
- **CONDUIT006** — *Misapplied [AuditAs]* (Error): a member carries `[AuditAs]` but is not `JsonElement`/`JsonElement?`, or its argument names no `string` property of the type or a base. Checked on every message (same scope as CONDUIT005, via `DispatchableTypeInfo.AuditAsMisuses`) and on every type a discovered message carries (`RoslynScanner.ScanCarriedAuditAsMisuses` -> `ConduitModel.CarriedAuditAsMisuses`, one `CarriedAuditAsMisuse` per type): a BFS over property types and public non-copy constructor parameter types (base chain included), through nullables, arrays and generic arguments, restricted to types `CanCarryAuditMarks` accepts -- declared in `compilation.Assembly`, or in a referenced assembly that is or references `Conduit.Contracts` (cached per assembly; the BCL and third-party packages are not walked) -- reported with `Location.None` like every message diagnostic, keyed on each type's `OriginalDefinition` (a use site's type arguments are reached through `Constituents` first; then the definition is walked once, so an expanding generic like `Tree<T>` -> `Tree<Tree<T>>` terminates and `Wrapper<A>`/`Wrapper<B>` report once as `Wrapper<T>`), with the `seen` set guarding cycles and reports keyed by (name, assembly identity), so same-named types from two assemblies each report; a carried type that is itself a message is left to the message check. Interface/type-parameter members are not walked. `Scan(compilation, messageSymbols)` collects the message symbols for that walk, so it adds no second pass over the compilation's types. `ConduitRuntime.ApplyAuditMemberMarks` writes a misapplied member as the placeholder rather than throwing, which is all an unchecked type gets.
- Generated `AddConduit()` calls `ConduitRuntime.AddConduitCore()` and registers handlers/listeners by interface type (e.g. `ICommandHandler<T,R>`, `IEventListener<T>`) — enables test substitution
- Generated `AddConduit()` also registers `ConduitTypeRegistry` with `typeof()` expressions for all discovered message types (`eventTypes:`, `commandTypes:`, `queryTypes:`) — compile-time verified, no runtime DI scanning needed by transports
- Pipeline behaviors resolved via `ConduitRuntime.ResolvePipelines` (explicit ordering, not DI enumeration)
- Types without handlers get route-only overloads (throw if no route matches)
- Microsoft.CodeAnalysis.CSharp version must be ≤ the SDK's Roslyn version (currently 4.12.0 for .NET 10 SDK)
