# Conduit.SourceGen (netstandard2.0)

- `EnforceExtendedAnalyzerRules=true`, `IsRoslynComponent=true`, `NoWarn=RS2008`
- Auto-discovers ALL types implementing `ICommand`, `IQuery`, `IEvent` across the full compilation graph (no attributes needed). Cross-assembly discovery is intentional for shared contract libraries. Discovery walks `compilation.GlobalNamespace` plus referenced assemblies via `RoslynScanner` — discovery-by-interface across non-source (metadata) assemblies cannot be expressed through syntax providers / `ForAttributeWithMetadataName`, so the whole-`Compilation` walk is required.
- **Incrementality (emission cached; walk is not):** `ConduitGenerator.Initialize` wires `CompilationProvider.Select(BuildModel).WithTrackingName("BuildModel")` → `.Select(ConduitModel.WithoutLocations).WithTrackingName("EmissionModel")` → `RegisterSourceOutput(Emit)`, and the full model `.Combine(CompilationProvider)` → `RegisterSourceOutput(ReportDiagnostics)`. `BuildModel` produces a value-equatable `ConduitModel` (records + `EquatableArray<T>`, no `ISymbol`/`Compilation` captured), so Roslyn skips re-emission when discovery is unchanged (asserted by `IncrementalCachingShould`). **The cross-assembly symbol walk still re-runs every keystroke** because its input (`Compilation`) always changes and discovery-by-interface across metadata assemblies can't use `ForAttributeWithMetadataName`; only the emission is cached. Hard rule: never capture a `Compilation`/`ISymbol` in `ConduitModel` — it silently defeats the cache. Listener-group order is pinned (`OrderBy` on the event type name) so the cached model is deterministic across `Dictionary` enumeration order.
- **Nested-type FullTypeName parity contract:** `DispatchableTypeInfo.FullTypeName` and the handler/event message-type keys (`HandlerInfo.MessageFullTypeName`, `ListenerGroup.EventFullTypeName`) hold the **metadata** full name — nested types joined to their container with `+` (e.g. `Ns.Outer+Inner`), matching the runtime `Type.FullName`, the wire discriminator, the `ConduitTypeRegistry` key, and `Conduit.TypeGen.ReflectionScanner` (which uses `type.FullName`). `RoslynScanner.GetMetadataFullName` builds this by walking the `ContainingType` chain (not a string-replace), from each type's `MetadataName` (a generic carries its arity, `Ns.Wrap`1`) and each namespace's unescaped `Name` (`ToDisplayString()` would write `App.@namespace`; `Type.FullName` is `App.namespace`). Because this metadata form is invalid C# source for nested and keyword-named types, emitters call `EmitConstants.ToCSharpTypeRef` (`+`→`.`, and `@` before every keyword segment: `App.@namespace.@event`) whenever the name is written into a **C# syntax position** (type declaration, generic argument, `typeof(...)`, cast) while emitting `FullTypeName` verbatim only into **string-literal discriminators**. Handler/listener implementation names (`HandlerFullTypeName`, `ListenerFullTypeNames`) and `ResultFullTypeName` stay in `ToDisplayString()` form (`.`, keywords already escaped) — they are only ever C# type references.
- **What `Scan` excludes.** A struct: a message is a class (Conduit's attributes are class-only, and the generated REST mapping and `HandleEvent` constrain to reference types; with Conduit.Transport.Http referenced a struct message failed the build with CS0452), and `ScanHandlers` skips a listener whose event is a value type. `ReflectionScanner.Scan` skips value types too. A message the generated code cannot name: one not accessible within `compilation.Assembly` (`compilation.IsSymbolAccessibleWithin` — private/protected, nested in such, `private protected`, or internal to a referenced assembly) or file-local (or nested in a file-local type) — `IsNameableByGeneratedCode`, the same test `ScanHandlers` applies to handlers and listeners (a file-local handler is CONDUIT004) — a generic one (`IsGenericType`, which includes a type nested in a generic type: reported as CONDUIT007 through `ConduitModel.GenericMessageTypes`), and every copy of a full type name that more than one assembly declares (CONDUIT008, `ConduitModel.DuplicateMessageTypes`). So `DispatchableTypes` is unique by `FullTypeName`, which the emitters rely on (`RegistrationEmitter`'s `ToDictionary`, one overload per type). `ScanHandlers` skips a handler/listener interface whose message argument is generic, skips a listener interface whose event argument is not `IsNameableByGeneratedCode` (internal to a referenced assembly, private, file-local, or a type parameter of an open generic listener), and `BuildModel` drops the listener groups of a duplicated name: a listener group is emitted unjoined, by its event's name (`IEventListener<TEvent>` and the registry's `typeof`), so its event must be nameable. A handler needs no such check: `RegistrationEmitter` emits one only joined to a discovered message (and an inaccessible handler still reports CONDUIT004). CONDUIT007/008 are reported before `Emit`'s empty-model early return.
- **The in-process switches dispatch on the exact type (`MediatorEmitter`).** The `IMediator` fallbacks (`ExecuteAsync<TResult>`, `ExecuteAsync`, `FetchAsync<TResult>`), `PublishLocalAsync`'s switch, the `shouldBroadcast` switch, and the `[FireAndForget]` capture/enqueue/bypass checks match `x.GetType().FullName` (`RuntimeTypeName`) against `FullTypeName` string literals — the wire switch's contract — and cast the matched message through `object` (`ExactCast`; an `ICommand<TResult>` does not convert to a sealed message type). Never a type pattern: with one message deriving from another, type-pattern arms overlap (CS8510/CS8120, an error, in discovery order), and a derived message would reach its base's handler. **The broadcast gate fails closed:** `shouldBroadcast` lists every discovered event that is not `[LocalOnly]` `=> true` and answers `_ => false`, so a runtime type the generator never discovered (private, file-local, internal to a referenced assembly) is not broadcast; with no broadcastable event no gate or broadcast is emitted.
- **The broadcast loop (`MediatorEmitter.EmitBroadcastBlock`)** sends the event to each transport in its own try/catch and logs a failure with `ConduitRuntime.LogTransportBroadcastFailure(logger, transport.GetType().Name, eventEnvelope.Type, ex)` (EventId 22), never `LogListenerFailure`: a transport is not a listener (`MediatorEmitterShould.LogATransportsBroadcastFailureAsTransportBroadcastFailed`).
- Reads `[LocalOnly]` attribute to suppress event broadcast in generated code. `[LocalOnly]` and `[FireAndForget]` are inherited (`AttributeUsage`'s default `Inherited = true`), so `RoslynScanner.GetInheritedAttribute` walks `BaseType` (the type's own first, then the nearest base, as `GetCustomAttribute(inherit: true)` does); `GetAttributes()` alone sees only the type's own declaration. `[DoNotAudit]` stays per type: the runtime reads it with `inherit: false`.
- Reads `[FireAndForget]` attribute: F&F void commands emit `Execute` (background dispatch) + `ExecuteVoidWire` (inline for wire-inbound). F&F events enqueue local listeners to background dispatcher, broadcast to transports inline. CONDUIT003 diagnostic for F&F on result types/queries. The generated `ILocalEnvelopeDispatcher.IsFireAndForget(fullTypeName)` lists the F&F void commands and events (`Immediate` included; never a result command or query, which the routed path still sends as a request) so `TransportDispatcher` sends a relayed routed F&F command with `SendEventAsync`, as the inline routed path does. `IsEvent(fullTypeName)` lists every discovered event, so `TransportDispatcher` broadcasts a relayed event and never routes it.
- Reads `[assembly: RemoteContracts("Ns")]` to suppress CONDUIT001 for types in remote contract namespaces and the namespaces beneath them, matched on whole segments (`ConduitGenerator.IsRemoteContract`: the full type name equals the pattern, or continues it with `.`), so `"Inventory"` does not cover `InventoryAudit.*`
- Reads `[NotAutoRegistered]` (`Conduit.Attributes.NotAutoRegisteredAttribute`) in `RoslynScanner` to exclude a handler/listener from auto-registration: `ScanHandlers` skips the type entirely, so it is neither registered nor counted (no CONDUIT002 against it, and a command whose only handler is `[NotAutoRegistered]` gets CONDUIT001). A message type carrying it is still discovered as a message
- **The attempt boundary (`DispatchEmitter`).** The handler-running `ConduitDispatch` methods keep their public signatures and become a call to `ConduitRuntime.DispatchAttemptsAsync<TRequest, TResult>(serviceProvider, attemptServices => <Method>Attempt(request, attemptServices, conduitOptions, cancellationToken), cancellationToken)`; the old body moves, unchanged, to a private `ExecuteAttempt` / `FetchAttempt` / `ExecuteVoidWireAttempt`. Command with a result: `Execute` / `ExecuteAttempt` over `Task<TResult>`; void command: `DispatchAttemptsAsync<TCmd, object>` with an async lambda returning `(object)Unit.Value`; query: `Fetch` / `FetchAttempt`; `[FireAndForget]` wire: `ExecuteVoidWire` / `ExecuteVoidWireAttempt`, still answering `Unit`. The `[FireAndForget]` local `Execute` (the enqueue) and a plain void command's `ExecuteVoid` (the wire path's object-returning wrapper over `Execute`, which is routed) are not routed through the boundary themselves; a `[FireAndForget]` command has no `ExecuteVoid`, as its wire path calls `ExecuteVoidWire`. `EmitDispatchParameters` and `EmitAttemptsCall` write the shared parameter list and the call; every type position goes through `EmitConstants.ToCSharpTypeRef` (a nested type's `+` form is not valid C#). Without a policy, nested, or uncovered, the runtime calls the attempt once on `serviceProvider`, so the emitted dispatch behaves as if the body were inline.
- **Starting the context (`MediatorEmitter.EmitContextStart`).** `StartDispatch`, `AttachObserver`, `BindDispatchAttempt`, the audit capture (`SerializeToElement(..., AuditJsonOptions)`) and `DispatchInvoked` run in a `try` whose bare `catch` restores the caller's context and rethrows; then the metric start, `using var __activity` and the dispatch's own `try`/`catch`/`finally`, unchanged. Deliberately not inside the dispatch's own `try`: its `catch` observes `DispatchFailed`, and a failure before `DispatchInvoked` would reach observers with no start (they key on `DispatchInvoked` coming first, and a custom observer may read `context.Payload` at `DispatchInvoked`, which `AuditDispatchObservationsShould.CapturePayloadOnDispatch` pins), so a capture that throws is reported to no observer and counted by no metric, as before. The caller never saw the dead context (an `async` method's builder restores the caller's `ExecutionContext`, `MediatorContextShould` pins it), so this is defensive: the generated method no longer leaves a started context unrestored. `MediatorEmitterShould.StartEveryInProcessContextInsideATryThatRestoresTheCaller` pins the shape. `EmitWireContextStart` (the transport owns that context) and `PublishLocalEnvelopeAsync` keep theirs.
- **Binding the context (`MediatorEmitter`).** `EmitContextStart` and `EmitWireContextStart` emit `ConduitRuntime.BindDispatchAttempt(MessageContext.Current, serviceProvider);` on the line after `AttachObserver` and before the first observation, via `EmitBindDispatchAttempt`. A top-level dispatch's context is started before `ConduitDispatch` runs, so it binds to no attempt and stays one context across every attempt; a dispatch from the running attempt's own scope binds to that attempt. The model is unchanged (no `ISymbol` captured).
- **Dispatch metrics (`MediatorEmitter`).** Every dispatch the mediator observes -- the in-process `ExecuteAsync`/`FetchAsync`/`PublishAsync`, the wire `DispatchRequestAsync`/`DispatchEventAsync`, and the outbox's `PublishLocalEnvelopeAsync` -- emits `__dispatchType`/`__dispatchKind` (deconstructed from a `(Type, Kind)` tuple) and its stopwatch through `EmitDispatchMetricStart`, then calls `ConduitTelemetry.RecordDispatch` exactly once: `success: true` beside each `DispatchCompleted` (`EmitDispatchCompleted`), `success: false` in the catch that observes `DispatchFailed` (`EmitDispatchFailed`). The kind is lowercase `command`/`query`/`event`. A wire request's tuple comes from the emitted `WireRequestMetric(type)` switch over the compilation's declared commands and queries, and a wire event's or outbox envelope's from `EventMetric(type)` over its events: the type name is the caller's, so a name the compilation does not declare (route-forwarded, or handled nowhere) is tagged `UndeclaredMetricType` (`(undeclared)`; kind `request` or `event`) and a caller cannot mint metric series. The audit observation's kind (`Request`/`Event` on the wire) is unchanged.
- **The wire request call (`MediatorEmitter`).** The generated `HandleWireRequestAsync` is `=> ConduitRuntime.HandleWireRequest(envelope.Type, interceptors, () => envelope, DispatchRequestAsync, logger, serviceProvider, cancellationToken);` -- the service provider, not one argument per service, so the runtime resolves the translators itself and the next runtime service needs no generator change (the refusal renderer and culture resolver are used at the transport edges, not here). `IWireMediator`'s signature is unchanged. An unknown type is a refusal, never an `InvalidOperationException`: `DispatchRequestAsync`'s default arm throws `ConduitRuntime.UnknownMessageType(logger, type)` (logs Warning, returns the `BadRequestException`), `DispatchEventAsync`'s throws `new Conduit.Exceptions.BadRequestException("Unknown message type '...'.")` directly, since `HandleWireEvent` logs every refusal itself. Each event arm reads with `ConduitRuntime.DeserializeWireEvent<T>(payload)` (lenient, an unreadable payload a `BadRequestException`), the request arms with `DeserializeWire<T>`. (`PublishLocalEnvelopeAsync`'s default stays an `InvalidOperationException`: the outbox's own envelope, not a caller's.)
- Emits: `ConduitDispatch.g.cs`, `ConduitRegistration.g.cs`, `ConduitMediator.g.cs`, `ConduitRestEndpoints.g.cs` (conditional; `internal static class` in `Microsoft.AspNetCore.Builder`, because every assembly that sees Conduit.Transport.Http emits one and two public ones make the host's `MapConduit*` calls ambiguous, CS0121; the verb methods' arms are written by `RestEmitter.EmitArms`), `ConduitResilienceDispatch.g.cs` (conditional)

## Diagnostics (`DiagnosticDescriptors.cs`)

- **Where they point.** `DispatchableTypeInfo.Location` and `HandlerInfo.Location` (`SourceLocation(FilePath, Start, Length)`, Conduit.Analysis: strings and ints, so the model stays value-equatable) are set by `RoslynScanner.SourceLocationOf` for a type of `compilation.Assembly` -- its first in-source location, the name's span -- and are null otherwise: a referenced assembly's type has no source, and in the IDE a project reference's symbols are "in source" in another compilation's tree, which a generator may not report in. The diagnostics are a second output, `model.Combine(context.CompilationProvider)` -> `ReportDiagnostics`, so `ToLocation` can rebuild `Location.Create(tree, span)` in the compilation's own tree, found by `FilePath`. Only an in-tree location honours `#pragma` and gets an IDE squiggle: `Location.Create(path, span, default)` prints as line 1 and suppresses nothing (measured), so it is only the fallback when no tree matches. That output re-runs on every compilation change, like the walk. `Emit` reads `ConduitModel.WithoutLocations()` (tracking name `EmissionModel`): a location moves with any edit above a declaration -- a comment at the top of a file, a property added to an earlier record, a handler body above a second handler -- so with locations in its input every such edit would re-emit every generated file. `BuildModel` is `Modified` by such an edit and `EmissionModel` `Unchanged` (`IncrementalCachingShould.KeepTheEmissionCachedWhenAnEditMovesADeclaration`, which also checks the diagnostic moves). Hard rule beside the one above: nothing diagnostic-only that moves with an edit goes into the emission's input. CONDUIT001/003/005/006 point at the type; CONDUIT002 at the type with each handler as an additional location (ordered by file and position; the first handler when the type is a referenced one); CONDUIT004/007/008 and a carried type's CONDUIT006 stay `Location.None`.

- **CONDUIT001** — *No handler found* (Warning): a command or query has no local handler and is not marked as a remote contract. Suppress for remote contract namespaces with `[assembly: RemoteContracts("Ns")]`.
- **CONDUIT002** — *Multiple handlers found* (Error): more than one handler exists for a command/query; only one handler per command/query is allowed.
- **CONDUIT003** — *Invalid [FireAndForget] usage* (Warning): `[FireAndForget]` is only valid on void commands (`ICommand`) and events (`IEvent`). Commands with results (`ICommand<TResult>`) and queries (`IQuery<TResult>`) require a response.
- **CONDUIT004** — *Handler not accessible* (Warning): a handler for a type exists in a referenced assembly but is not accessible to the generating assembly. Make it `public` to be auto-registered.
- **CONDUIT005** — *Conflicting audit marks* (Error): a message member (property or record/constructor parameter, base chain included) is marked both `[DoNotAudit]` and `[AuditRedacted]`; an audited member takes one. Mirrors the runtime refusal in `ConduitRuntime.ApplyAuditMemberMarks`.
- **CONDUIT006** — *Misapplied [AuditAs]* (Error): a member carries `[AuditAs]` but is not `JsonElement`/`JsonElement?`, or its argument names no `string` property of the type or a base. Checked on every message (same scope as CONDUIT005, via `DispatchableTypeInfo.AuditAsMisuses`) and on every type a discovered message carries (`RoslynScanner.ScanCarriedAuditAsMisuses` -> `ConduitModel.CarriedAuditAsMisuses`, one `CarriedAuditAsMisuse` per type): a BFS over property types and public non-copy constructor parameter types (base chain included), through nullables, arrays and generic arguments, restricted to types `CanCarryAuditMarks` accepts -- declared in `compilation.Assembly`, or in a referenced assembly that is or references `Conduit.Contracts` (cached per assembly; the BCL and third-party packages are not walked) -- reported with `Location.None` (a carried type records no `SourceLocation`), keyed on each type's `OriginalDefinition` (a use site's type arguments are reached through `Constituents` first; then the definition is walked once, so an expanding generic like `Tree<T>` -> `Tree<Tree<T>>` terminates and `Wrapper<A>`/`Wrapper<B>` report once as `Wrapper<T>`), with the `seen` set guarding cycles and reports keyed by (name, assembly identity), so same-named types from two assemblies each report; a carried type that is itself a message is left to the message check. Interface/type-parameter members are not walked. `Scan(compilation, messageSymbols)` collects the message symbols for that walk, so it adds no second pass over the compilation's types. `ConduitRuntime.ApplyAuditMemberMarks` writes a misapplied member as the placeholder rather than throwing, which is all an unchecked type gets.
- **CONDUIT007** — *Generic message types are not supported* (Error): a concrete command/query/event is generic or nested in a generic type; it has no full type name the generated code can write, so nothing is emitted for it (an `abstract` generic base is not a message and is not reported).
- **CONDUIT008** — *Message type declared in more than one assembly* (Error): two or more assemblies declare a message with the same full type name (`DuplicateMessageType.Assemblies` names them, ordinal-sorted); every copy is left out of the model, so the generated code never names the ambiguous type and `RegistrationEmitter` never sees a duplicate key.
- Generated `AddConduit()` calls `ConduitRuntime.AddConduitCore()` and registers handlers/listeners by interface type (e.g. `ICommandHandler<T,R>`, `IEventListener<T>`) — enables test substitution
- Generated `AddConduit()` also registers `ConduitTypeRegistry` with `typeof()` expressions (`RegistrationEmitter.EmitTypeRegistry`) — compile-time verified, no runtime DI scanning needed by transports: `eventTypes:` every discovered event, `commandTypes:`/`queryTypes:` those with a handler, `listenedEventTypes:` the listener groups' events, `clientVisibleEventTypes:` the events whose `DispatchableTypeInfo.IsClientVisible` (`[ClientVisible]` read through the base chain, like `[LocalOnly]`). It is the **first** statement, before `AddConduitCore` runs `configure`, so a feature registering a listener there (`AddJobs`, `AddAuditListener`) finds the instance and calls `ActivateEvent`.
- Pipeline behaviors resolved via `ConduitRuntime.ResolvePipelines` (explicit ordering, not DI enumeration)
- Types without handlers get route-only overloads (throw if no route matches)
- Microsoft.CodeAnalysis.CSharp version must be ≤ the SDK's Roslyn version (currently 4.12.0 for .NET 10 SDK)
