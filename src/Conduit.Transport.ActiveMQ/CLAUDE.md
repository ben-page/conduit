# Conduit.Transport.ActiveMQ

User guide: [`docs/transports/activemq.md`](../../docs/transports/activemq.md) — setup, options, configuration keys, topology, pools, wire format. Keep user-facing facts there, not here.

- `ActiveMQTransport` — extends `BrokerTransportBase<ActiveMQInboundMessage>`. Uses `AmqpNetLite` (AMQP 1.0). Inbound dispatch, lifecycle, and outbound serialization handled by base class. Implements Artemis-specific primitives: AMQP 1.0 connection/session management, two-address publishing, exclusive reply queue correlation, receiver link management.
- `UseActiveMQ(connectionString?, configure?)` registers everything **keyed by endpoint name** — options, `ActiveMQTransport` (via `ActivatorUtilities.CreateInstance`, resolving the keyed options), a forwarding non-keyed `IConduitTransport` entry and a forwarding non-keyed `IHostedService` entry (each resolving the endpoint's keyed transport instance) — and calls `UseTransport<ActiveMQTransport>()`. No non-keyed `ActiveMQTransport`/options registration exists.
- **Artemis only**, not ActiveMQ "Classic": topology is created through the Artemis management address (`activemq.management`), which Classic does not expose.
- Two addresses, `{systemName}-commands` (ANYCAST) and `{systemName}-events` (MULTICAST). Command/query queues are shared, named per type, and carry a `JMSType='{FullTypeName}'` filter; event queues are per-app on the multicast address. The broker enforces unicast here, so unlike RabbitMQ correctness does not depend on only one app binding a type.
- Reply queue is a per-instance exclusive temporary queue, destroyed on shutdown.
- AMQP 1.0 wire mapping (`BuildOutboundApplicationProperties`): `Subject`=FullTypeName, native `MessageId`, native `CorrelationId`=ConversationId; `ApplicationProperties` carry the historical `CausationId` (plus `ReplyTo`/`ReplyCorrelationId` for requests) **alongside** the canonical `conduit-message-id`/`conduit-causation-id`/`conduit-conversation-id`/`conduit-source-app` keys — every header the base class assembles is additionally written under its canonical `ConduitHeaders` name. `conduit-source-app` is read by the [self-published event filter](../Conduit/CLAUDE.md) on the inbound side.
- Topology modes use Artemis's native `auto-delete-delay` (Production durable, Developer 4h, Test 5min), so ephemeral resources self-clean — no reaper needed, unlike Kafka and Amazon SQS.
- `DefaultConcurrency` / `ReceiverPoolOptions.Concurrency` both map to the receiver link credit (prefetch count).
- Type discovery via `ConduitTypeRegistry` (source-generated, compile-time verified) — no runtime DI scanning.
- All configuration keys bind directly through `ConduitConfigurationBinder.BindTransportOptions` — no exclusions, no hand-mapping (`Username`/`Password` are plain strings).
