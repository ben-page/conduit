# Conduit (core)

No ASP.NET dependency — only DI abstractions, Hosting abstractions, Logging abstractions, Options,
and `Microsoft.Extensions.Configuration.Binder`.

## Runtime types

**IntelliSense hygiene.** Public types that generated code and sibling packages call but a host never names carry
`[EditorBrowsable(EditorBrowsableState.Never)]`: `ConduitRuntime`, `ConduitTelemetry`, `TransportDispatcher`,
`DispatchContextEnrichment`, `ConduitConfigurationBinder`, `ILocalEnvelopeDispatcher`, `ConduitBackgroundDispatcher`,
`WirePreflightResult` (and `ConduitRestHandlers` in Conduit.Transport.Http), plus the member
`ConduitRuntime.SuppressAuditPayloadOf`, public only so Conduit.Audit reaches it without an `InternalsVisibleTo`
(Conduit grants one only to its own test projects). `MessageContext.Payload`, the other member Audit reads, is plainly
public: the captured body, readable by any `IConduitObserver`. Deliberately left visible because hosts name them: `ConduitTypeRegistry` (`GetRequiredService<ConduitTypeRegistry>().ExcludeEventTypes(...)`), `IWireMediator`
(a batch handler, a custom transport), `RefusalRendering` (a host's own edge calls `RenderResult`), `DispatchAttempt`
(`Current`, read by behaviors), `ConduitHeaders` (wire contract). The attribute hides a type from completion only:
naming it still compiles. `TypeFilterInterceptor` is internal (its test is in Conduit.Tests).

- `ConduitRuntime` — static class centralizing route resolution, transport resolution (keyed DI), inbound gate chain, pipeline chaining, error handling. `HandleWireRequest`/`HandleWireEvent` run `IInboundInterceptor` gates before deserialization, then dispatch. Called primarily by source-generated mediator code. The generated mediator calls the `HandleWireRequest(..., ILogger logger, IServiceProvider services, CancellationToken)` overload, which resolves only the `IWireExceptionTranslator`s from `services` (the next runtime service needs no generator change). `HandleWireRequest` and `PreflightWireRequestAsync` render nothing: a refusal is English and `DispatchError.Text` (never serialized) carries its sentence name and values. `HandleWireEvent` rethrows a `ConduitException` (a gate's refusal, an unknown type) after a Warning without the exception (EventId 7 `RefusedEvent`), for the edge to answer: HTTP `/publish` and the hub's `Publish` render it, `BrokerTransportBase.DispatchEventAsync` acknowledges it, after offering a `BadRequestException`/`ContractMismatchException` to the dead-letter store. The generated wire event switch reads each event with `DeserializeWireEvent<T>` (lenient `JsonOptions`, but a `JsonException` or JSON null becomes `BadRequestException("The event could not be read at '{path}'.")`), so an unreadable event is a refusal the edge answers or a broker dead-letters, no longer a `JsonException` `HandleWireEvent` logged and swallowed. `RunWireRequestAsync` and `HandleWireEvent` rethrow an `OperationCanceledException` only `when (cancellationToken.IsCancellationRequested)` (the caller gave up): activity status set, no log, no reference; any other OCE is an unexpected failure. `UnknownMessageType(logger, type)` (public) logs Warning EventId 8 and returns the `BadRequestException("Unknown message type '{type}'.")` the generated wire switch's default arm and the preflight throw (the generated wire *event* switch throws the same exception directly; `RefusedEvent` logs it). The wire request activity's `conduit.message.kind` is `request`, as the metric tags an undeclared one.
- `RefusalRendering` (public static) — writes a refusal in the reader's language at the edges where an answer leaves the server: `RenderResult(result, services, context)` (envelope endpoint, hub; message and each detail) and `RenderMessage(text, english, services, context)` (REST `detail`). Both do nothing — no DI lookup, same instance back — unless there is `Text` to render, and never throw: resolving the `IDispatchCultureResolver` or `IRefusalTextRenderer` from `services`, the resolver's `Resolve`, and the renderer are each guarded and fall back to the English, logging at Error under `RefusalRendering`'s category (EventId 21 `DispatchCultureResolveFailed`, EventId 20 `RefusalTextRenderFailed`). `ResolveCulture`, `Render` and `RenderDetails` are the public pieces. An in-process caller gets English plus `DispatchError.Text` and calls `RenderResult` at its own edge, or rethrows a refusal carrying the `Text`. `DispatchResult<T>.Fail(exception)` sets `Text`; the unexpected answer carries `ConduitTextNames.UnexpectedError`. The exception, `Activity` status and every log line keep the English. `DispatchPropertyCultureResolver` (one property, a fixed case-insensitive map, throws `ArgumentException` for two keys that differ only by case; anything else answers null, never builds a `CultureInfo` from the value) is the ready-made resolver.
- `ConduitRuntime.DispatchAttemptsAsync<TRequest, TResult>(services, attempt, ct)` — the dispatch boundary every generated handler-running `ConduitDispatch` method calls (`Execute`, `Fetch`, `ExecuteVoidWire`; `[EditorBrowsable(Never)]`). Non-async. Runs `attempt(services)` once, on `services`, when no `DispatchRetryRunner` is in DI (`AddDispatchRetry` never called), when the dispatch is nested (`DispatchAttempt.Current.Services` is `services` by `ReferenceEquals`), or when `IDispatchRetryPolicy.Covers(typeof(TRequest))` is false; otherwise `DispatchRetryRunner.RunAsync`. `ConduitRuntime.BindDispatchAttempt(context, services)` sets `MessageContext.Attempt` to `DispatchAttempt.Current` under the same `ReferenceEquals` rule (else null); the generated mediator calls it right after starting a dispatch's context. User docs: `docs/dispatch-retry.md`.
- `IDispatchRetryPolicy` / `DispatchAttemptFailure` (`Conduit.Runtime`) — the host's contract: `Covers(Type)` and `RetryReason(DispatchAttemptFailure)` (a reason string, or null to stop). Asked inside the failed attempt's still-open scope (`AttemptServices`), for the last attempt too (a reason there is `exhausted`), never for an attempt that ends in an `OperationCanceledException` with the dispatch's own token cancelled (any other exception is asked about, token cancelled or not). A throwing policy is logged (EventId 19, Warning) and treated as null. Conduit knows no failure kinds; the host's policy decides.
- `DispatchRetryOptions` / `DispatchRetryDelay` (`Conduit.Configuration`) — `MaxAttempts` (3), `Delays` (`(10ms,100ms)`, `(50ms,300ms)`; before attempt n+1 the range is `Delays[min(n-1, Count-1)]`, drawn uniformly with `Random.Shared`), `TimeProvider` (default `TimeProvider.System`, deliberately never the DI clock). `Validate()` is internal, run by `AddDispatchRetry<TPolicy>`, which registers the policy, the options and `DispatchRetryRunner` as singletons and throws if a `DispatchRetryRunner` descriptor already exists.
- `DispatchRetryRunner` (internal, singleton) — the attempt loop, no per-dispatch state. Copies `MaxAttempts`, `Delays` (an array) and `TimeProvider` in its constructor and never reads the options object again (it stays resolvable and mutable; validation is `AddDispatchRetry`'s). Each attempt: `await using` a scope from the root `IServiceScopeFactory`, `DispatchAttempt.SetCurrent`, run, restore `Current` in `finally`. The try/catch only *decides*: success; OCE with the dispatch's token cancelled (kept, policy not asked); other failure -> ask the policy inside the scope; null reason or `number >= maxAttempts` -> kept, count `exhausted` if a reason was given; else `Abandon()`, count `retried`, `MessageContext.Observe(RetryAttempted)` on the dispatch's own context, log EventId 17. A kept attempt's `Keep()` runs *after* the try/catch/finally, still inside the scope, so kept work that throws is never offered to the policy (then EventId 18 on a success after attempt 1). Once the scope is disposed, `ReleaseServices()` (in a `finally`), then return the result, or rethrow the kept failure via `ExceptionDispatchInfo`, or `Task.Delay(delay, timeProvider, ct)`.
- `DispatchAttempt` (public sealed) — `Current` (an `AsyncLocal`, private; set only by the runner), `Number`, `MaxAttempts`, internal `Services` (null once the runner disposed the attempt's scope, so a flowed `Current` pins nothing and matches no live provider). `OnKept(Action)`: queued while undecided; after the decision, runs at once if kept and is dropped if abandoned; thread-safe (lock covers the queue and the decision, work runs outside it). The first decision is final: a second `Keep()`/`Abandon()` is a no-op. `Keep()` runs every queued action in order on the deciding thread, even when one throws, then rethrows the one failure as itself (`ExceptionDispatchInfo`) or several as an `AggregateException`; that reaches the dispatch's caller in place of its result or the attempt's own exception, never the policy. So it should not throw. `MessageContext.Attempt` is the public property the audit observer reads.
- Dispatch telemetry — counter `conduit.dispatch.count` and histogram `conduit.dispatch.duration` (ms) via `ConduitTelemetry.RecordDispatch`, whose only callers are the generated mediator's dispatch paths (see `src/Conduit.SourceGen/CLAUDE.md`). Tags `conduit.message.type` (the `FullName`, or `(undeclared)` for a wire or envelope type the host does not declare -- the caller names it, so it is never a tag), `conduit.message.kind` (`command` | `query` | `event`, or `request` for an undeclared wire request), `conduit.outcome` (`success` | `error`: the dispatch threw). One dispatch per host is one measurement; a remote-routed request counts on the sender and again, as a wire request, on the receiver.
- Retry telemetry — counter `conduit.dispatch.retries` (`ConduitTelemetry.RecordDispatchRetry`, internal; tags `conduit.message.type` = the request's `FullName`, `conduit.retry.reason`, `conduit.retry.outcome` = `retried` | `exhausted`). Logs: 17 `DispatchRetrying` (Information, no exception), 18 `DispatchRetrySucceeded` (Information), 19 `DispatchRetryPolicyFailed` (Warning); EventIds 17-19 follow 1, 2, 4-8, 10-16 in `ConduitRuntime`; 22 is `TransportBroadcastFailed` (Error, `LogTransportBroadcastFailure(logger, transportName, typeName, exception)`): the generated publish's broadcast loop logs a transport whose `SendEventAsync` threw under it, naming the transport and the event, and carries on to the next transport. It used to log it as `ListenerFailed` (4, "Event listener 'SignalRTransport' threw..."), sending a reader after a listener that does not exist (`EventBroadcastShould.LogATransportsFailureAsTransportBroadcastFailed`).
- `ConduitRuntime.PreflightWireRequestAsync(contractName, payload, services, ct)` -> `WirePreflightResult(Admitted, DispatchError? Refusal)` — a wire request's inbound checks without its handler. Shares `RunWireRequestAsync` (activity, context handling, gate loop, exception-to-wire mapping, translators) with `HandleWireRequest`; the body is `RunInboundChecksAsync`: routed contract -> admitted unread; contract looked up by `FullName` in `ConduitTypeRegistry` command/query types (unknown -> `UnknownMessageType` -> a `BadRequest` refusal, as the wire answers); `DeserializeWire<T>`; the `options.PipelineTypes` that are assignable to `IInboundCheckBehavior`, in order, closed over `ResultTypeOf(contract)` (the `ICommand<T>`/`IQuery<T>` argument, else `object`) by a per-call `MakeGenericMethod` (no cache), chained by `ExecuteWithBehaviors` around a no-op step. Runs no other behavior, no `Validate()`, attaches no observer. The caller's `MessageContext` is hidden for the call (`RestoreContext(null)`) and restored in `finally`. `Admitted` is true only when the checks ran and there is no error; `(false, null)` is a gate's discard. `IInboundCheckBehavior` (`Conduit.Middleware`) is an empty marker interface by design (CA1040 suppressed): the runtime reads it from the pipeline's types in code, not a test.
- `ConduitRuntime.JsonOptions` — camelCase, case-insensitive names; `JsonStringEnumConverter` (names only, no ordinals)
  and `ClosedSetJsonConverterFactory` (`Conduit.Runtime`, public): a closed set (`IClosedSet<TSelf>`) as its bare
  `Value`, read back by Ordinal match to the very member, any other token a `JsonException` (so a JSON-pathed 400 from
  `DeserializeWire`); the converter checks `[ClosedSet]` against `All` once per type and throws on a difference. Both
  SignalR transports copy these converters into their payload options, and `AuditJsonOptions` is built from
  `JsonOptions`. The HTTP envelope and REST endpoints read and write with `JsonOptions` too, never the host's ASP.NET options.
- `MessageContextIds.IsValid(string?)` (public static, `[NotNullWhen(true)]`) — whether a caller-supplied correlation id is a plain token, `^[A-Za-z0-9-]{1,64}$` (`GeneratedRegex`) matched over the WHOLE string: `$` also matches before a final `\n`, so it also checks the match length (`MessageContextIdsShould` pins `"abc\n"`). The HTTP wire endpoint and `ConduitHub` honor a trusting edge's caller ids only through it, and the C# `HttpTransport`/`SignalRTransport` forward a context only when all three ids pass it (broker-delivered ids are never checked on the way in); `HandleWireRequest` uses it to decide whether the `ConversationId` is log-safe as the support reference.
- `TransportDispatcher` — singleton service encapsulating route resolution + transport dispatch. `SendAsync(envelope, localDispatcher, ct)` broadcasts an event (`localDispatcher.IsEvent`) with `SendEventAsync` to every registered transport (its constructor's `IEnumerable<IConduitTransport>`: the non-keyed singleton forwarders the generated publish broadcasts to) and never routes it, or sends nothing for a `[LocalOnly]` one (`IsLocalOnly`). Otherwise it resolves routes via `ConduitRuntime.ResolveRoute`, then sends via the endpoint's keyed transport -- `SendEventAsync` when `localDispatcher.IsFireAndForget(envelope.Type)` (a `[FireAndForget]` void command or event: no reply, as the generated mediator's routed path), else `SendRequestAsync` -- or broadcasts to all transports (`SendEventAsync`). The caller passes the `ILocalEnvelopeDispatcher` it resolved from its own per-entry scope (null without the generator: every routed send is a request); the singleton never resolves the mediator itself, because the mediator takes the scoped `IInboundInterceptor`s (the inbox's) and root resolution throws under scope validation. Registered by `AddConduitCore`. Used by `OutboxRelay` and `OutboxCapture.ClaimAndDeliverAsync` (the routine `OutboxCapture.FlushAsync` schedules on `ConduitBackgroundDispatcher`) instead of duplicating transport resolution logic.
- `TypeFilterInterceptor` (internal sealed, in `Conduit.Middleware`) — `IInboundInterceptor` gate, run for every inbound message (events too), that throws `ForbiddenException` (403, not `UnauthorizedException`/401 — the caller is authenticated, the type just isn't client-dispatchable) for types not in `TypeFilterOptions.AllowedTypes`. Configured via `conduit.AddTypeFilter()`.
- `TopologyNaming` — generates shared resource names (`CreateSharedResourceName`) and app-scoped resource names (`CreateAppResourceName`) with consistent prefix/truncation/hashing across all transports. Every name goes through the private `Finish`: compose (a dotted suffix reversed by `ReverseSegments`), `Sanitize` (public, so a caller can match a raw segment such as the SQS reaper's prefix: every char outside `[A-Za-z0-9_-]` becomes `-`, one for one — a Windows `DOMAIN\user` prefix, a dotted application name, a nested type's `+`), then, over `maxLength`, the first `maxLength - 9` chars + `-` + the first 8 hex chars of `XxHash64` (`x16`) of the **whole sanitized name**. It used to hash only a dotted suffix (XxHash32), so two long application names sharing the kept prefix and one message type collided (`TopologyNamingShould.KeepLongSiblingNamesDistinct` pins the exact format; `.SanitizeNestedTypesAndWindowsUserNames`). Changing either step renames deployed queues. `BrokerTransportOptions.IsReservedPoolName` (internal) compares a pool name's sanitized form, ignoring case, with `replies` (the reply queue's suffix) and `dead-letter` (held for a broker-side dead-letter queue a transport may name per application; RabbitMQ's is one per system, `{system}-dead-letter`, which no pool name produces): `AddPool` throws `ArgumentException` (`TopologyNamingShould.RejectReservedPoolNames`) and `ConduitConfigurationBinder.ValidatePoolNames` `InvalidOperationException` (`TransportOptionsBindingShould.RejectAReservedPoolName`), since the binder fills `Pools` without `AddPool`.
- `ConduitTypeRegistry` — compile-time registry of event, command, and query message types. Properties: `EventTypes`, `CommandTypes`, `QueryTypes` (Type lists) and pre-computed `EventTypeNames` (a set: **every** discovered event, listened for or not -- `BrokerTransportBase.IsEventType` reads it), `ClientVisibleEventTypeNames` (a set: discovered events marked `[ClientVisible]`, inherited), `CommandTypeNames`, `QueryTypeNames` (lists). `ActiveEventTypeNames` is the events this host listens for, which brokers subscribe: the generator's listened events (`listenedEventTypes:`; null = all), plus `ActivateEvent(fullTypeName)` (idempotent, thread-safe: a lock around a copy-on-write list) for a listener registered at runtime -- `AddJobs` per trigger event, `AddAuditListener` for `AuditBatch`, `ConduitRegistrationOverrides.Apply` per `HandleEvent` (after `ClearEventListeners`' `ExcludeAllEventTypes`). `ExcludeEventTypes` filters the current active list. Populated by source generator in `AddConduit()` with `typeof()` expressions, registered **before** the `configure` callback runs so `AddJobs`/`AddAuditListener` find the instance in `builder.Services` (a hand-made `ConduitBuilder` has none; they skip). Broker transports resolve from DI for topology discovery instead of scanning `IServiceCollection` at runtime. Each registry also adds its message types (unfiltered by exclusions; only `ICommand`/`IQuery<T>`/`IEvent` implementers) to a process-wide static lookup by `FullName` (`TryGetRegisteredMessageType`, internal), which the static `ConduitRuntime.AuditJsonOptions` reads to type an `[AuditAs]` member -- no `Type.GetType` on a wire name.
- `ApplicationName` on `ConduitOptions` defaults from `IHostEnvironment.ApplicationName` at first resolution via factory registration in `AddConduitCore`. No transport-side mutation needed.
- `ConduitBackgroundDispatcher` — `BackgroundService` with unbounded `Channel<T>` for F&F work items. Registered in DI by `AddConduitCore`. Sequential execution, linked cancellation for graceful shutdown.
- `BrokerTransportBase<TMessage>` — abstract base class for all 4 broker transports (ASB, RMQ, SQS, ActiveMQ). Owns `IHostedService` lifecycle, inbound dispatch orchestration (context save/restore, the self-published-event filter, scope creation, request/event branching, error handling), and outbound send (serialization, reply unwrap via `ConduitRuntime.UnwrapReply`). Transports implement ~15 abstract methods for transport-specific primitives. Uses `BinaryData` for payload passing. `StartAsync` branches on `ProducerOnly`: true → `ConnectAsync` + `EnsureOutboundTopologyAsync`; false → `ConnectAsync` + `EnsureTopologyAsync` + `StartConsumersAsync`. `EnsureOutboundTopologyAsync` is an abstract method for producer-only topology (reply queue + topic/exchange only). `StopAsync(token)` is three steps then `FailPendingReplies`: abstract `StopReceivingAsync` (a new hook, not the old `StopConsumersAsync`: stop taking inbound messages — RabbitMQ `BasicCancel` of the inbound consumers, ActiveMQ `SetCredit(0)`, SQS cancels its app/pool pollers, ASB `StopProcessingAsync` — leaving channels/links/clients and the reply consumer open, since a drained handler may await a reply; called on producer-only hosts too), protected `DrainInFlightAsync(token)`, then abstract `StopConsumersAsync` (close inbound channels/links/receivers and the reply consumer; anything unacknowledged is redelivered). Both hooks must tolerate an expired token. Tracking: `ProcessInboundMessageAsync` is a wrapper that, under one `Lock`, adds a placeholder `TaskCompletionSource` task to a `HashSet<Task>` unless `draining`, runs the old body (now private `DispatchInboundMessageAsync`), and removes/completes the placeholder in `finally` (so a drained task never faults; the wrapper still rethrows to its caller as before). `DrainInFlightAsync` sets `draining` and snapshots the set under the same lock (so nothing is admitted after the snapshot), waits `Task.WhenAll(...).WaitAsync(token)` with `SuppressThrowing`, never throws, and logs EventId 508 `DrainAbandoned` (Warning, count) at the deadline. A message delivered while draining is returned undispatched via `AbandonAsync` (best effort, EventId 509 `MessageReturnedOnStop`, Debug). Protected static `WaitUntilDeadlineAsync(operations, token)` waits for already-started stop/close calls until the token fires and observes the rest in the background: RabbitMQ's channel close and ASB's `StopProcessingAsync`/`CloseAsync` all wait for a running handler regardless of any token (measured), which would otherwise hold `StopAsync` past the deadline. Tests: `BrokerTransportShutdownShould` (FakeBrokerTransport records `Lifecycle`), per-broker `{Transport}ShutdownShould`. Outbound metadata is assembled once per publish by the base class into a fresh `Dictionary<string, string>` keyed by `ConduitHeaders.*` — correlation IDs from `MessageContext.Current`, W3C trace context from the current `Activity`, and the publishing application's name (`ConduitOptions.ApplicationName`, omitted when unset) — and passed to `PublishRequestAsync`/`PublishEventAsync`. Transports are dictionary-to-native-property mappers and keep their historical on-wire names; no transport holds ambient outbound state. **Dead-letter capture** (`TryCaptureErrorAsync(services, message, type, exception, reference)`, the `IInboundErrorInterceptor`): a failure before dispatch (context, unreadable body, scope or mediator) goes to `SettleUndispatchableAsync` — capture through a fresh scope, else acknowledge (never abandon: it would fail the same way forever); an event refused as `BadRequestException`/`ContractMismatchException` (the generated event read, `ConduitRuntime.DeserializeWireEvent`, or an unknown type) is captured, else acknowledged, while any other event refusal (`ForbiddenException`) is acknowledged uncaptured (`BrokerTransportDeadLetterShould.CaptureAnEventItsTypeCannotRead`, `.NotCaptureAForbiddenEvent`); a request is captured only when its result's `Error.Code == ErrorCode.InternalError.Value`, passing `Error.Reference`, so a refusal (404/409/412, any `ConduitException`) is never dead-lettered, and is acknowledged only when not captured (a capture acknowledges; it used to be acknowledged again, which RabbitMQ answers by closing the channel — `BrokerTransportDeadLetterShould.AcknowledgeACapturedRequestOnce`); an `EventListenerException` and a thrown F&F dispatch are captured, else abandoned. A capture's acknowledgement runs outside `TryCaptureErrorAsync`'s guard: one that throws propagates to the broker client, never a second settlement or a `DeadLetterStoreFailed` log (`.SettleACaptureOnceWhenItsAcknowledgementFails`). **Redelivery** (`RedeliverAsync(envelope, RedeliveryIds? ids, ct)`, DLQ replay): each broker builds its metadata with the protected static `BuildRedeliveryHeaders(ids)` — the original `MessageId`/`CausationId`/`ConversationId` under `ConduitHeaders` keys (a fresh message id alone when `ids` is null), nothing else, no source-app stamp — and maps it with its own publish mapper. `RedeliveryIds` (sealed record, get-only properties so `with` cannot bypass it) throws `ArgumentException` for any blank id (`RedeliveryIdsShould`).
- `ConduitHeaders` — well-known keys for the outbound header dictionary `BrokerTransportBase` assembles once per publish (`MessageId`, `CausationId`, `ConversationId`, `SourceApp`). These name **in-process** dictionary entries; each transport maps them onto its own native property model and keeps its existing on-wire names. Transports must not read ambient state (`MessageContext.Current`, static fields) on the outbound path — the dictionary is the only source.
- **Self-published event filter** (`BrokerTransportBase.ProcessInboundMessageAsync`) — drops an inbound event whose `ConduitHeaders.SourceApp` stamp matches this host's own `ApplicationName`, because that application's listeners already ran inline when `PublishAsync` published it. An application's own listeners therefore always run **on the publishing instance**, never load-balanced across replicas — the fix removes the extra broker-delivered execution rather than redistributing the work. Placed immediately after `MessageContext.StartDispatchFromTransport` (so the skip observation isn't dropped — `MessageContext.Observe` no-ops without a current context) and before `CreateAsyncScope` (so a filtered message costs neither a DI scope nor a deserialize); acknowledges rather than abandons, to avoid a redelivery loop. Four details make the guard correct: it keys on the **application**, not the instance — `ApplicationName` is shared by every replica, so an instance-scoped stamp would let a peer replay the listeners; it recognizes events via `ConduitTypeRegistry.EventTypeNames`, not `!IsRequest` — a routed `[FireAndForget]` command also arrives with `IsRequest == false`, and filtering on that alone would silently drop a command an application routed to itself or a peer; it requires `ApplicationName` to be non-empty before comparing — without that guard, a missing stamp on *any* inbound event, including one from a non-Conduit producer, would compare equal to an unset `ApplicationName` and be silently discarded, so an unnamed application would drop every inbound event rather than none; and a missing or non-matching stamp always dispatches normally, so pre-upgrade messages and non-Conduit producers are unaffected. Emits `SelfPublishedEventSkipped` (a `MessageObservation`) on drop, so a dropped listener run is visible to any registered `IConduitObserver` (see [Audit](../../docs/audit.md)) instead of silently disappearing.
- `BrokerTransportOptions` — abstract base for all 4 broker options classes. Owns `DefaultConcurrency` (int, default 10), `ResponseTimeout` (default 60 s), `EndpointName` (`protected set`, so the binder skips it; each derived options class has an `internal` constructor taking the endpoint name, which its `Use*` extension calls, plus an explicit public parameterless one), the `Pools` list, and `AddPool(name, configure)`. Concrete transport options inherit it and add only broker-specific settings. The base transport's constructor takes it, exposes it as `Options`, and reads `EndpointName` from it (no longer a virtual override per transport).
- `ReplyCorrelator` (internal sealed) — pairs replies with waiting requests by correlation id. `Register(correlationId, messageType, endpointName)` returns an `IDisposable` (dispose = release; it settles an unawaited waiter as cancelled so a racing `FailAll` leaves no unobserved fault); `WaitAsync(correlationId, timeout, ct)` is `Task.WaitAsync(timeout, TimeProvider, ct)` over the waiter, rewriting its own `TimeoutException` (only `when` the waiter is still incomplete, so a `FailAll` exception passes through) to `NoReply(...)`: `"No reply to '{type}' from endpoint '{endpoint}' within {timeout}."`; `Complete` does not remove the entry (a reply that arrives before `WaitAsync` is kept); `FailAll(exception)` faults every incomplete waiter. `BrokerTransportBase` holds one (`TimeProvider.System`): `SendRequestAsync` mints the correlation id, registers it **before** calling `PublishRequestAsync(envelope, body, headers, correlationId, ct)` (returns `ReadOnlyMemory<byte>`), and disposes it after. Protected surface: `AwaitReplyAsync(correlationId, ct)` (bounded by `Options.ResponseTimeout`; `OperationCanceledException` only for the caller's token), `CompleteReply(correlationId, body)` (the body must outlive the call — RabbitMQ copies `args.Body`), `FailPendingReplies(exception)` (`StopAsync` calls it last, with `InvalidOperationException("The transport for endpoint '{endpoint}' stopped before the reply arrived.")`), and `CreateReplyTimeoutException(messageType)` for Azure Service Bus, which receives its reply from the request's own session (`ReceiveSessionReplyAsync`) and never awaits the registered waiter. Tests: `ReplyCorrelatorShould`; each broker's `TimeoutWhenNoHandlerAvailable`/`TimeoutQueryWhenNoHandler` pin the exact exception and message.
- `ReceiverPoolOptions` — single shared named-pool config: `Name` (required), `Concurrency` (int, default 1), `MessageTypes` (`IReadOnlyList<string>`, exposed read-only; populate via `Handle(fullTypeName)`, `Handle<TMessage>()`, or `Handle(Type)` — all three resolve to `FullTypeName` and de-duplicate, so calling any of them twice with the same type is a no-op). `Concurrency` is interpreted per broker (prefetch for RabbitMQ/ActiveMQ, max-concurrent-calls for ASB, polling parallelism for SQS); transports cast to the broker-native type at the consumption site (e.g. `(ushort)` for RabbitMQ prefetch).
- `ConduitConfigurationBinder` (`Conduit.Configuration`) — static helper, `BindTransportOptions(BrokerTransportOptions options, IConfiguration? section, params string[] excludedKeys)`. Called by each broker transport's `Use*` extension before its `configure` callback runs. No-ops when `section` is null or has no children. Validates every `Pools` entry has a unique, non-empty `Name` (the binder itself would bind a missing required `Name` as `""` rather than throwing) — throws `InvalidOperationException` naming the offending configuration path otherwise. Binds everything except `excludedKeys` (and null values) by projecting the section through `AsEnumerable(makePathsRelative: true)`, rebuilding it as an in-memory configuration, and calling `Bind(options)` — `excludedKeys` exists because the binder throws on abstract/interface-typed properties it cannot construct (e.g. `AmazonSqsOptions.Credentials`). Then hand-adds each pool's `MessageTypes` via `Handle(...)`, because `ReceiverPoolOptions.MessageTypes` is a getter-only `IReadOnlyList<string>` that the binder skips silently.

## Configuration

`AddConduit()` is generated by source gen. All configuration goes through `ConduitBuilder`: `AddEndpoint`, `AddPipeline`, `AddTypeFilter`. `AddEndpoint` throws `ArgumentException` for a null/blank name or one already added (before running `configure`, so no second keyed transport is registered); `AddPipeline` throws `ArgumentException` unless the type `IsGenericTypeDefinition` with two type parameters and implements `IPipelineBehavior<,>` -- a closed or other-arity type used to fail at the first dispatch, in `ResolvePipelines`' `MakeGenericType`. Routing is configured per-endpoint via `ConduitEndpointBuilder.RouteNamespace<T>()` and `ConduitEndpointBuilder.RouteType<T>()`.

`TopologyMode` enum (Production/Developer/Test) and `SystemName`/`TopologyPrefix` properties on `ConduitOptions` control topology resource naming and durability across broker transports.

`ConduitBuilder.UseConfiguration(IConfiguration)` binds the five `ConduitOptions` scalars
(`SystemName`, `ApplicationName`, `TopologyMode`, `TopologyPrefix`, `ProducerOnly`) explicitly,
property by property — never `section.Bind(options)`, because `Endpoints`/`Routes`/`PipelineTypes`
are code-owned shapes the binder would mangle or choke on. It stores the resolved section on
`ConduitBuilder.Configuration` for `ConduitEndpointBuilder` to slice into `Endpoints:{name}` per endpoint.
Source-generated `AddConduit(IServiceCollection, IConfiguration, Action<ConduitBuilder>?)` (emitted
by `RegistrationEmitter`, `src/Conduit.SourceGen/`) just calls `UseConfiguration` then the callback —
config binds first, code always wins.

`BrokerTransportOptions.AddPool(name, configure)` is **get-or-create**: if a pool with that name
already exists (typically because configuration produced it), `configure` runs against the existing
pool instead of appending a duplicate. Name matching is `OrdinalIgnoreCase`; since configuration
binds first and creates the instance, the configuration's spelling of `Name` is what survives into
broker resource naming. Combined with `ReceiverPoolOptions.Handle`'s de-duplication,
a pool declared in both configuration and code ends up with the union of both sources' message
types rather than two competing pools. See [`docs/configuration-reference.md`](../../docs/configuration-reference.md#loading-from-iconfiguration)
for the full picture, including per-transport configuration key tables.

**Measured binder behaviours.** Every row below was verified against the real
`Microsoft.Extensions.Configuration.Binder` (with the real `AWSSDK.SQS`
types), not inferred from its documentation. They are the reason `ConduitConfigurationBinder` has
the shape it has — re-measure before "simplifying" any step away, because each one that goes back
takes a silent misconfiguration with it.

| Binder behaviour | Consequence in the code |
|---|---|
| A getter-only `List<ReceiverPoolOptions> Pools` **does** bind — entries are created with their `Name` and `Concurrency` | pools never need hand-constructing; the helper only fixes up what the binder misses |
| A getter-only `IReadOnlyList<string> MessageTypes` is **silently skipped** — the pool binds but routes nothing | `BindTransportOptions` re-walks the pool sections afterwards and hand-adds each type via `Handle(...)` |
| A `Pools` entry missing the `required` `Name` binds as `""` rather than throwing | `ValidatePoolNames` runs first and throws `InvalidOperationException` naming the offending configuration path |
| A blanket `Bind` **throws** on an abstract/interface-typed property (`AmazonSqsOptions.Credentials` is an `AWSCredentials`) and binds `RegionEndpoint` to **null silently** | `excludedKeys` projects a key and its whole subtree out before binding; Amazon SQS excludes `Region` + `Credentials` and hand-maps both |
| Non-public setters are skipped | `BrokerTransportOptions.EndpointName { get; protected set; }` cannot be hijacked from configuration — the endpoint's identity is not a setting (`TransportOptionsBindingShould.NotBindTheEndpointNameFromConfiguration`) |
| Enum members bind by name (`"Developer"`), `TimeSpan` parses from `"00:00:30"`, and an absent key yields null | `UseConfiguration` assigns only when the key is present, so unset keys leave defaults alone |

**Rejected alternatives** (recorded so they are not re-proposed without new information):

- `services.AddOptions<T>().BindConfiguration(...)` with `IOptions<T>` resolution — idiomatic, and it would enable reload-on-change, but it defers binding past registration, which is exactly where the required-value validation runs, and it changes how all six transports consume their options.
- A `ConnectionStrings:{endpointName}` fallback — a familiar .NET convention, but it puts the same value in two discoverable places and mirrors no builder call, breaking the key-name rule.
- Config wins over code — rejected in favour of code-wins so an explicit `UseRabbitMQ("amqp://prod")` can never be silently redirected by a stray appsettings entry.
- `Conduit:Endpoints:{name}:{Transport}` nesting — redundant, since an endpoint has exactly one transport. And `Conduit:Transports:{Transport}` — cannot express two endpoints on the same broker technology with different connection strings.
- Growing `ConduitEndpoint` to hold its transport options so the runtime object graph matches the configuration shape — core cannot reference the transport packages, so the property would have to be `object?`, a weaker contract than the keyed DI registration that already owns it.

**Trim/AOT.** `Microsoft.Extensions.Configuration.Binder` is reflection-based, so the
`AddConduit(IConfiguration, ...)` path is the one reflective seam in an otherwise source-generated
library. It runs at registration time only, and only for applications that opt into it. Nothing in
the repo sets `IsTrimmable` today, so this is a constraint to settle before publishing trimmable or
AOT-friendly packages rather than a present defect — but it does qualify the "reflection-free,
compile-time" positioning, and a code-only host never touches it.

## Wire dispatch route forwarding

The generated `DispatchRequestAsync` checks routes before the local type switch. Unknown types matching a route are forwarded as raw envelopes to the transport without deserializing locally.

## Exceptions

- `ErrorCode` — enumeration class pairing a machine-readable code string with HTTP status code. Value-based equality. Built-in codes: `NotFound`, `Unauthorized`, `Forbidden`, `Conflict`, `PreconditionFailed`, `InternalError`, `BadRequest`, `ContractMismatch`. `ErrorCode.ToHttpStatusCode(string)` maps wire code strings to HTTP status codes (single source of truth for both RESTful and envelope endpoints). Consumers define their own.
- `ConduitException` — abstract base with `ErrorCode Code` property; its protected constructor throws `ArgumentNullException` for a null code (it used to surface as a `NullReferenceException` thrown from inside `RunWireRequestAsync`'s `catch (ConduitException)` arm, where the wire reads `Code`, escaping it). `GetClientData()`/`GetClientType()` expose a subclass's own public properties (declared below `ConduitException`, via `ClientDataProperties(Type)`) to the wire; `null` for a plain status exception. `DispatchResult<T>.Fail(ConduitException)` carries that onto `DispatchError.Status`/`Type`/`Data`.
- `ContractMismatchException` (sealed, code `ContractMismatch`, 400) -- thrown by `ConduitRuntime.DeserializeWire` when a wire request omits a constructor parameter that has no C# default, at any depth of positional models; `Details` = one `(wirePath, "missing")` per member (`eTag`, `columns[0].wipLimit`), computed from the contract walked against the payload. `DeserializeWire` reads with a private `WireReadOptions` (`JsonOptions` + `RespectRequiredConstructorParameters`); NEVER set that flag on the shared `JsonOptions` -- it also reads stored job payloads, replies and events, which must stay lenient. Names at most 20 (the rest counted in the message; no data property, so not client-typed), a dictionary value as `name[*]` (never the client's key), reflection cached per type. A settable/`init` property of a non-positional model is not checked, nor a struct without `[JsonConstructor]` (STJ binds its setters; `BoundConstructor` mirrors that); the RESTful endpoints read leniently; broker-delivered and DLQ-replayed commands are strict (a broker-routed command's new member needs a default). Naming failures fall back to `BadRequest`, never a 500.
- Concrete: `BadRequestException`, `NotFoundException`, `UnauthorizedException`, `ForbiddenException`, `ConflictException`, `PreconditionFailedException` — not sealed; subclass to declare a refusal's client-facing data as public properties
- `RemoteDispatchException` (`Conduit.Runtime`, sealed, an `InvalidOperationException`) — what `ConduitRuntime.UnwrapReply` throws for a reply carrying a `DispatchError`. `Code` is an `ErrorCode` built from `DispatchError.Code` with `DispatchError.Status` (or `ErrorCode.ToHttpStatusCode(code)` from a server predating `Status` — the HTTP endpoint's rule; a blank code reads as `InternalError`), so a consumer's own code keeps its status; `Reference` is the remote support reference. `Conduit.Resilience`'s `TransientErrors<T>()` retries it only for `InternalError` (`WireRequestFailureShould.PutTheRemoteCodeOnTheExceptionUnwrapReplyThrows`).
- `EventListenerException` — infrastructure exception (not a `ConduitException`) thrown when event listeners fail, by an inline local `PublishAsync` (to the publisher) and by wire dispatch. Carries `IReadOnlyList<Exception> ListenerExceptions` (required: a null list throws `ArgumentNullException`); `InnerException` is the first of them (none when the list is empty), so `GetBaseException()` reaches the root cause. Transports catch this to decide complete vs abandon. A `[FireAndForget]` event's background listeners log it instead.
