# Conduit.Transport.AzureServiceBus

- `AzureServiceBusTransport` — extends `BrokerTransportBase<ProcessMessageEventArgs>`. Inbound dispatch, lifecycle, and outbound serialization handled by base class. Implements ASB-specific primitives: session-based replies, topic publishing, processor management, topology creation.
- `UseAzureServiceBus(connectionString?, configure?)` registers everything **keyed by endpoint name** — options, `AzureServiceBusTransport` (via `ActivatorUtilities.CreateInstance`, resolving the keyed options), a forwarding non-keyed `IConduitTransport` entry and a forwarding non-keyed `IHostedService` entry (each resolving the endpoint's keyed transport instance) — and calls `UseTransport<AzureServiceBusTransport>()`. No non-keyed `AzureServiceBusTransport`/options registration exists: two endpoints on Azure Service Bus are two independent transport instances with independent options, never a shared last-write-wins singleton.
- Wire format: message body = serialized message (JSON), type in `Subject` property, MessageContext in native `MessageId`/`CorrelationId` properties + historical `CausationId` application property (`SeedOutboundMessageContext`, preserved so `ExtractContext` keeps working unchanged). Every header from the base class's assembled dictionary is additionally written into `ApplicationProperties` under its canonical `ConduitHeaders` key (`conduit-message-id`, `conduit-causation-id`, `conduit-conversation-id`, `conduit-source-app`), so both the historical and canonical forms are on the wire. `conduit-source-app` carries the publishing application's `ApplicationName` (omitted when unset) and is read by the [self-published event filter](../../docs/transports/index.md#self-published-events) on the inbound side.
- Request/response via ASB sessions on a reply queue (`{systemName}-{appName}-replies`): the base class's correlation id is the reply's session, and `ReceiveSessionReplyAsync` accepts that session rather than awaiting the base class's reply waiter (Service Bus keeps the reply until the session is accepted, so no reply consumer is needed). Its timeout is the base class's `TimeoutException` (`CreateReplyTimeoutException`).
- **All messages flow through the topic**: commands, queries, and events all publish to the shared topic. Subscriptions with SQL filters (`Subject = '{FullTypeName}'`) forward to the handler's app queue. Replies are the only exception (point-to-point to reply queue).
- **Unicast subscriptions** (commands/queries): shared name via `TopologyNaming.CreateSharedResourceName` — only one app receives each message
- **Multicast subscriptions** (events): per-app name via `TopologyNaming.CreateAppResourceName` — every subscribing app gets a copy
- Topology: try-create with 409 swallowing, always created on startup (idempotent). Supports topology modes (Production = durable, Developer = 4h auto-delete, Test = 5min auto-delete). Resource names generated by `TopologyNaming`.
- Receiver pools for concurrency isolation (`AddPool()` on options). Options inherit `BrokerTransportOptions` (core): `DefaultConcurrency` and `ReceiverPoolOptions.Concurrency` both map to the processor's max-concurrent-calls.
- Type discovery via `ConduitTypeRegistry` (source-generated, compile-time verified) — no runtime DI scanning
- **Configuration keys** (`Conduit:Endpoints:{endpointName}`, bound by `ConduitConfigurationBinder.BindTransportOptions` before the `configure` callback runs): `ConnectionString` (required), `AdminConnectionString` (optional, defaults to `ConnectionString`, binds directly), `DefaultConcurrency` (default `10`), `ResponseTimeout` (default `00:01:00`), `Pools` (array of `{ Name, Concurrency, MessageTypes[] }` — see `AddPool` merge semantics in `src/Conduit/CLAUDE.md`). See [`docs/configuration-reference.md`](../../docs/configuration-reference.md#loading-from-iconfiguration) and [`docs/transports/azure-service-bus.md`](../../docs/transports/azure-service-bus.md#loading-from-configuration).

## Test caveats

**Azure Service Bus emulator**: The emulator has a hard cap of 50 queues+topics combined per namespace (not configurable — see [Azure/azure-service-bus-emulator-installer#48](https://github.com/Azure/azure-service-bus-emulator-installer/issues/48)). `AsbTestBase` tracks per-test topology prefixes via `AsyncLocal` and deletes topics + matching queues in `[TestCleanup]` to stay under the quota. `[assembly: DoNotParallelize]` forces sequential class execution for the same reason. If `Conduit:AzureServiceBus:ConnectionString` is set in user secrets (pointing at a real namespace), pass `Conduit__AzureServiceBus__ConnectionString=""` to force the emulator path.
