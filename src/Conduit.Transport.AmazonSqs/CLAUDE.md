# Conduit.Transport.AmazonSqs

- `AmazonSqsTransport` — extends `BrokerTransportBase<AmazonSqsInboundMessage>`. Uses AWS SDK (`AmazonSNSClient` + `AmazonSQSClient`). Inbound dispatch, lifecycle, and outbound serialization handled by base class. Implements SNS/SQS-specific primitives: SNS publishing, SQS long-polling consumers, reply queue correlation, topology creation.
- `UseAmazonSqs(configure?)` registers everything **keyed by endpoint name** — options, `AmazonSqsTransport` (via `ActivatorUtilities.CreateInstance`, resolving the keyed options), a forwarding non-keyed `IConduitTransport` entry and a forwarding non-keyed `IHostedService` entry (each resolving the endpoint's keyed transport instance) — and calls `UseTransport<AmazonSqsTransport>()`. No non-keyed `AmazonSqsTransport`/options registration exists: two endpoints on Amazon SQS are two independent transport instances with independent options, never a shared last-write-wins singleton. No connection string — uses Region or ServiceUri (for LocalStack).
- SNS topic for all messages, SQS queues per app, SNS subscriptions with filter policies route by type
- Commands/queries: shared subscription names (unicast). Events: per-app subscription names (multicast).
- Reply via direct SQS send (bypasses SNS). Message attributes: `Type`; `MessageId`, `CausationId`, `ConversationId` — renamed from the canonical `conduit-*` keys, because SNS/SQS cap a message at 10 attributes and a request publish already uses 9 of them (`Type`, `MessageId`, `CausationId`, `ConversationId`, `traceparent`, `tracestate`, `conduit-source-app`, `ReplyQueueAddress`, `CorrelationId`), leaving only **one** spare attribute. These three are renamed rather than duplicated to stay under the ceiling (see `BuildOutboundAttributes`/`ToAttributeName` in `AmazonSqsTransport`); `ReplyQueueAddress`, `CorrelationId` (both requests only); and `traceparent`/`conduit-source-app`, which travel under their canonical `ConduitHeaders` keys like everything else outside the three renamed correlation IDs. `conduit-source-app` carries the publishing application's `ApplicationName` (omitted when unset) and is read by the [self-published event filter](../../docs/transports/index.md#self-published-events) on the inbound side.
- Raw message delivery required on subscriptions (filter policies need it). Startup validates `RawMessageDelivery=true` and `VisibilityTimeoutSeconds >= ResponseTimeout`.
- SQS queue name limit is 80 characters — `TopologyNaming` hash truncation activates frequently.
- Topology modes: Production = standard, Developer/Test = prefixed resources.
- `AmazonSqsTopologyReaper.ReapByPrefixAsync(options, prefix)` — public best-effort cleanup that deletes SQS queues + SNS topics whose names start with `prefix` (deleting a topic removes its subscriptions). Used by the test harness (once per project) and available to apps. SNS/SQS clients are built by the shared `AmazonSqsClientFactory` (also used by the transport's `ConnectAsync`).
- Concurrency: options inherit `BrokerTransportOptions` (core). `DefaultConcurrency` and `ReceiverPoolOptions.Concurrency` map to the polling parallelism bound (the per-consumer `SemaphoreSlim` limit).
- Type discovery via `ConduitTypeRegistry` (source-generated, compile-time verified) — no runtime DI scanning
- **Configuration keys** (`Conduit:Endpoints:{endpointName}`, bound by `ConduitConfigurationBinder.BindTransportOptions` before the `configure` callback runs): `Region` (AWS system name, e.g. `"eu-west-1"`), `Credentials:AccessKey`/`Credentials:SecretKey`/`Credentials:SessionToken` (nested, never a flat key), `ServiceUri` (binds directly, for LocalStack), `DefaultConcurrency` (default `10`), `ResponseTimeout` (default `00:01:00`), `VisibilityTimeoutSeconds` (default `60`), `RawMessageDelivery` (default `true`), `Pools` (array of `{ Name, Concurrency, MessageTypes[] }` — see `AddPool` merge semantics in `src/Conduit/CLAUDE.md`). `Region` and `Credentials` are excluded from the generic bind and mapped by hand in `ApplyAwsConfiguration`: the binder resolves `RegionEndpoint` to `null` silently and throws outright on the abstract `AWSCredentials`. No `AccessKey`/`SecretKey` pair falls back to the default AWS credential chain. See [`docs/configuration-reference.md`](../../docs/configuration-reference.md#loading-from-iconfiguration).
