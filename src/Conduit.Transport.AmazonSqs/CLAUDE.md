# Conduit.Transport.AmazonSqs

User guide: [`docs/transports/amazon-sqs.md`](../../docs/transports/amazon-sqs.md) — setup, options, configuration keys, credentials, LocalStack, topology, pools, wire format. Keep user-facing facts there, not here.

- `AmazonSqsTransport` — extends `BrokerTransportBase<AmazonSqsInboundMessage>`. Uses AWS SDK (`AmazonSNSClient` + `AmazonSQSClient`). Inbound dispatch, lifecycle, and outbound serialization handled by base class. Implements SNS/SQS-specific primitives: SNS publishing, SQS long-polling consumers, the reply-queue poller (which hands each reply to the base class's `CompleteReply`), topology creation.
- `UseAmazonSqs(configure?)` registers everything **keyed by endpoint name** — options, `AmazonSqsTransport` (via `ActivatorUtilities.CreateInstance`, resolving the keyed options), a forwarding non-keyed `IConduitTransport` entry and a forwarding non-keyed `IHostedService` entry (each resolving the endpoint's keyed transport instance) — and calls `UseTransport<AmazonSqsTransport>(options)`, which refuses a `ResponseTimeout` that is not positive and finite. No non-keyed `AmazonSqsTransport`/options registration exists. No connection string — Region or ServiceUri.
- **The 10-attribute ceiling drives the wire format.** SNS/SQS cap a message at 10 message attributes and a request publish already uses 9 (`Type`, `MessageId`, `CausationId`, `ConversationId`, `traceparent`, `tracestate`, `conduit-source-app`, `ReplyQueueAddress`, `CorrelationId`), leaving **one** spare. The three correlation ids are therefore **renamed** from their canonical `conduit-*` keys rather than duplicated alongside them — see `BuildOutboundAttributes`/`ToAttributeName`. Adding another always-on attribute needs a plan for what comes off.
- **Raw message delivery is load-bearing, not a preference.** SNS filter policies match on message attributes, and attributes are only visible to a policy under raw delivery; without it SNS wraps the payload and every queue receives every message. Startup validates `RawMessageDelivery == true` and `VisibilityTimeoutSeconds >= ResponseTimeout` (a shorter visibility timeout redelivers a message while its caller still awaits the reply).
- SQS queue name limit is 80 characters — `TopologyNaming` hash truncation activates frequently here, more than on any other transport. App and pool queues are named at 76 (`AmazonSqsTopologyManager.AppQueueName`/`PoolQueueName`) so `DeadLetterQueueName` (`{queue}-dlq`) always fits; the reply queue, which has no DLQ, at 80.
- **Reply queue per instance** (CONDUIT-48): `{system}-{app}-replies-{instanceId}` (`AmazonSqsTopologyManager.ReplyQueueName`; the instance id is a fresh GUID, taken once by the transport's `field`-backed `ReplyQueueName`). A shared per-app reply queue let any instance poll any reply; the poller deletes every reply it reads, so with N instances (N-1)/N of replies were lost (`SqsCompetingInstanceShould.DeliverRepliesToTheInstanceThatAsked`). A reply nobody awaits is now necessarily late: deleted, Debug `LateReply` (111). The queue is deleted in `StopConsumersAsync` (after the reply poller stopped, with the shutdown token) and, if that failed or never ran, in `DisposeAsync` with its own 10 s timeout (Warning `ReplyQueueNotDeleted`, 112). The manager sets `ReplyQueueAddress` as soon as the queue exists, before `SetQueueAttributes`, and the transport records it even when a later start step throws (`KeepReplyQueueAddress`), so a host that fails to start on every restart does not leave one per attempt. The IAM actions every call needs are listed in the user guide's Permissions section; keep it in step with any new AWS call. A crashed instance leaves it behind; the Test-prefix reaper removes it.
- **Dead-letter queues** (CONDUIT-49): `CreateDeadLetteredQueueAsync` creates `{queue}-dlq` first (`MessageRetentionPeriod` 14 days: a moved message keeps its original enqueue time), then the queue with `RedrivePolicy {deadLetterTargetArn, maxReceiveCount: MaxReceiveCount}` (default 5, validated 1..1000 in `ValidateOptions`). The reply queue and the DLQs get none. `AbandonAsync` stays a no-op on purpose: the visibility timeout lapsing redelivers and SQS counts the receive, so the redrive policy ends the loop a visibility timeout per attempt. A pool whose queue name equals another queue's DLQ name (pool `dlq`) is refused at start.
- **Idempotent topology** (CONDUIT-50): `CreateOrUpdateQueueAsync` = `CreateQueue` with the full attribute set, on `QueueNameExistsException` `GetQueueUrl`, then `SetQueueAttributes` always (LocalStack enforces `QueueNameExists` for a changed `VisibilityTimeout`). `SubscribeAsync` = `Subscribe` with `RawMessageDelivery` + `FilterPolicy` (a new subscription is born filtered), on `InvalidParameterException` whose message says "already exists" `Subscribe` without attributes (AWS answers with the existing ARN), then `SetSubscriptionAttributes` for both always. LocalStack never refuses a re-subscription, so that catch path is unverified there (`SqsTopologyShould.ApplyChangedAttributesToAnExistingQueueAndSubscription` covers the read-back). Every queue's filter policy is planned and checked against SNS's 150-value ceiling (`FilterPolicy`, types distinct and ordinally sorted) before any AWS call.
- `AmazonSqsTopologyReaper.ReapByPrefixAsync(options, prefix)` — public best-effort cleanup deleting SQS queues + SNS topics by name prefix (deleting a topic removes its subscriptions). The prefix is sanitized first (`ResourceNamePrefix` = `TopologyNaming.Sanitize`), as resource names are: a raw `john.doe` matched none of the `john-doe-…` names (`Unit.AmazonSqsTopologyReaperShould`). Used by the test harness once per project; also available to apps. SNS/SQS clients come from the shared `AmazonSqsClientFactory`, also used by `ConnectAsync`.
- `AmazonSqsClientFactory.Create` builds both clients from a config (`AmazonSQSConfig`/`AmazonSimpleNotificationServiceConfig`): `Credentials` goes on `ClientConfig.DefaultAWSCredentials` whenever it is set, with or without `ServiceUri` (which only overrides the endpoint; `Region` then goes unused); with none, a `ServiceUri` gets the `test`/`test` placeholder pair and AWS the SDK's default chain. The SDK signs with `ExplicitAWSCredentials ?? Config.DefaultAWSCredentials` (decompiled `BaseAuthResolverHandler`, AWSSDK.Core 4.0), so the config is equivalent to the constructor argument and, unlike it (`protected internal`), readable: `Unit.AmazonSqsClientFactoryShould` asserts the clients carry a `Support/StubAwsCredentials`. Configured credentials used to apply only with `ServiceUri`, so against AWS they were silently replaced by the default chain.
- `DefaultConcurrency` / `ReceiverPoolOptions.Concurrency` map to the polling parallelism bound (the per-consumer `SemaphoreSlim` limit). The semaphores are fields (`pollerSlots`), disposed in `DisposeAsync`, never a `using` in the poll loop: a handler releases its slot after its poller has stopped (`ReleaseSlot` tolerates a slot disposed under a handler the shutdown deadline cut short). Handlers run in `Task.Run` with no token, so a message holding a slot always runs (or is handed back by the base class while draining). The `Task.Run` body catches what escapes `ProcessInboundMessageAsync` (a failed delete) and logs Error `InboundMessageFailed` (110): nothing else observes that task, and the poller never sees it. When polling stops while the poller waits for a slot, the rest of the received batch is made visible at once (`MakeVisibleAsync`: `ChangeMessageVisibilityBatch` to 0, best effort; an exception or `Failed` entries log Warning `MessagesNotMadeVisible`, 113, with the count), as `RequeueAsync` does for a message the drain returns (`SqsShutdownShould.HandBackReceivedButUnstartedMessagesAtOnce`: the poller is blocked on the slot, not in a long poll, so the LocalStack cancelled-poll quirk below does not apply).
- Stop: the app/pool pollers (`inboundPolling`) and the reply poller (`replyPolling`) have separate tokens. `StopReceivingAsync` cancels and awaits the inbound pollers only; the reply poller keeps running through the drain and stops in `StopConsumersAsync`, which then deletes the reply queue. LocalStack keeps serving a long poll the client cancelled (up to `WaitTimeSeconds`, 20 s) and can hand it a message, which then stays invisible for the visibility timeout as of the poll's start: a test that stops a host and expects the next host on the same queue to receive within seconds must use a short visibility timeout on the first. Whether real SQS does the same is unverified. `DisposeAsync` is idempotent: the keyed registration and both forwarders resolve the same instance, and the container disposes what each factory returns.
- Type discovery via `ConduitTypeRegistry` (source-generated, compile-time verified) — no runtime DI scanning.
- `Region` and `Credentials` are **excluded** from `ConduitConfigurationBinder.BindTransportOptions` and hand-mapped in `ApplyAwsConfiguration`: the binder resolves `RegionEndpoint` to null silently and throws outright on the abstract `AWSCredentials`. An incomplete `AccessKey`/`SecretKey` pair falls back to the default AWS credential chain.
